# v002 資料設計與相容策略

採用規劃中的建議預設：單層資料夾、一文件一歸屬、空資料夾可刪除、分類同步，以及 A4 白底一頁直式／橫式。這些是本輪採用的實作預設，不回溯描述為使用者逐項指定。

## 先確定的相容邊界

- IndexedDB 從版本 2 升至 3，只新增 `library` store，既有 documents／assets／settings 保留。舊文件沒有 membership 操作，視為未分類。
- 分類是獨立 `{format:1, kind:'library', operations:[]}` 因果圖。`folder:<ID>` 保存名稱或刪除 null；`member:<文件ID>` 保存 folderId 或未分類 null。它們都不是 PDF 文件，也不占用筆跡 ID。
- 文件改名仍在文件的 `$document` 圖，移動在 library 圖，因此改名與移動互不覆蓋。所有並行管理版本均保留；衝突頁另列「分類管理衝突」。
- `.pdfnote` 維持 format 1，不含 library 或歸屬。新文件／副本按當前檢視分類；合併既有文件只合併內容，不動其 membership。
- 新建文件增加可選 `origin:'blank'` 來源描述；舊格式缺少此欄位仍可讀。舊程式能繼續開啟基底與筆記，檔案格式不需升版。新程式以「匯出初始空白 PDF」明確區分外部原始檔。
- 空白 PDF 在建立時產生一次，初始來源 hash 與 PDF hash 相同，文件 UUID 各自獨立。方向改變真實 A4 寬高，PDF 旋轉維持 0。

## 本機原子性

新文件、資產、初始分類在同一 IndexedDB 交易提交。分類建立、改名、刪除與移動也使用交易，重新檢查本機重名、目的資料夾有效性及空資料夾條件。刪除空資料夾會檢查已刪除文件及所有候選歸屬，避免還原或解決版本時意外失去分類。

## 跨端競爭

library 使用独立 `type=library` 不可變 hash 快照，仍在 Google Drive appDataFolder。合併是操作聯集及 parents 圖，不以整份清單覆蓋。資產及文件與分類可分別到達；找不到有效資料夾、刪除／移入競爭或歸屬衝突時，文件顯示在全部文件及未分類並提示，不隱藏內容。

本機建立／改名會阻擋同名；兩端新增同名不同 ID，聯集後全部保留，介面提示改名並顯示短 ID。並行改名／移動及管理衝突的選擇結果可再次形成衝突，規則與筆跡相同。旧版 App 忽略新 `type=library` 快照，不會覆寫分類；兩端都更新至 0.2.0 才顯示新功能。
