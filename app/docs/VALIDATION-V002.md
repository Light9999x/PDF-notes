# v002／App 0.2.0 實作與驗收紀錄

日期：2026-09-18。範圍：資料夾整理、橫式／直式空白文件，以及啟動與關閉說明。沿用 v001 程式，沒有重建 App、改用原生安裝包或宣稱補完所有既有缺口。

## 採用的預設

採用 v002 建議的單層資料夾、一文件一歸屬、只刪除空資料夾、分類同步、A4 白底一頁及直式預設；它們是此次實作選擇，不回溯視為使用者逐項指定。資料設計、資料庫交易與相容策略見 [V002-DESIGN.md](V002-DESIGN.md)。

## 實作成果

- 資料夾建立／改名、重名及空名稱檢查、進出檢視、文件移入／移出、刪除空資料夾。
- 全部文件／未分類檢視、目前範圍內搜尋。資料夾刪除競爭、遺失或歸屬衝突會提示，文件仍可開啟。
- 獨立 library 因果圖與 Drive appDataFolder 快照；分類候選版本在衝突頁的管理資料區選擇。同名不同 ID 保留並標出短 ID。
- 本機新建真實 A4 直式或橫式 PDF，預覽方向、可輸入／自動命名；取消不建檔。建立成功與初始歸屬一起保存，再開啟現有編輯器。
- 無註記與有註記的新建文件均沿用兩種匯出；來源選單顯示「匯出初始空白 PDF」。每個文件 UUID 獨立，固定基底不重生。
- IndexedDB 2 → 3 升級新增 library，不清除舊文件／資產／設定；`.pdfnote` format 1 保持可讀，分類不混入單份存檔。
- 合併既有文件不動分類；新匯入與副本放入目前資料夾。
- README 已加入確認本機保存、關閉 Windows／Android／瀏覽器畫面、用 Ctrl+C 停止本機服務、重新啟動與升級步驟。

## 自動化驗證

執行環境：此 Windows 工作空間、Node.js 22.16.0、Microsoft Edge 的 Playwright 隔離瀏覽器。手機檢視為 412 × 915 的版面模擬，**不是 Galaxy S24+ 实機**。

| 檢查 | 結果／範圍 |
|---|---|
| `npm run check` | TypeScript 型別檢查通過 |
| `npm test` | 30 項通過：原 18 項，加 12 項分類及空白文件測試 |
| `npm run build` | 正式 PWA 建置、202 項離線資源清單檢查通過 |
| `npm run test:e2e` | 8 項通過：既有 5 項加 3 項 v002 流程，並擴充既有 Drive 模擬案例 |
| `npm ci --dry-run --offline --ignore-scripts --cache .npm-cache` | 鎖檔與套件安裝規劃檢查通過，未重新安裝套件 |

新增核心驗證：並行資料夾新增、同名不同 ID、不合法名稱、旧文件未分類、並行改名與解決結果再衝突、並行移動、刪資料夾／移入競爭、歸屬與改名獨立、非法版本圖、兩種真實 A4 尺寸、独立 UUID、空白存檔往返及四類物件資料往返。

新增端到端驗證：

1. 資料夾建立與改名、非空刪除拒絕、取消空白文件、兩種方向與無註記匯出、空白頁文字、文件移動不改 ID／PDF、重新匯入合併保留分類、副本放目前資料夾、未分類、離線重開及桌面／窄螢幕畫面。
2. 實際建立 IndexedDB v2 文件／資產／設定，再讓 App 升至 v3，檢查原內容及設定保留，舊文件與存檔仍可讀。
3. 注入 `QuotaExceededError` 模擬儲存失敗，確認沒有半完成文件；重開後重複點擊只產生一個文件。
4. 擴充 Drive 模擬傳輸：雙端離線建立同名資料夾、移動同文件至不同 ID、同時改文件名，確認名稱不遺失並保留歸屬衝突；管理版本擇一同步至另一端；空資料夾刪除與離線移入競爭後，文件仍在未分類且有提示。原有 429 重試及兩端筆記新增合併也仍涵蓋。

修正驗證期間發現的操作問題：文件選單在開啟移動／重新命名等操作後自動收起，避免下一次點選反而將選單關閉。

另將瀏覽器禁止 Service Worker 時的離線快取錯誤改成設定頁的清楚說明；不把技術錯誤冒充筆記儲存失敗，也不宣稱已可離線重開。測試中的 Drive 隔離環境會刻意封鎖 Service Worker，真實離線重開則由另一項允許快取的流程驗證。

- Windows 安裝後與 Galaxy S24+／Android 16 的手指操作、效能及跨平台匯入仍待實機驗證。
