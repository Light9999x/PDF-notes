## 文件手勢

閱讀容器在手勢開始前設 `touch-action:none`，不更改 body、全站 viewport meta 或 UI scale。閱讀／頁面模式的單指由容器捲動；PDF 原有文字層保留原生文字選取與選單，已有非空原生選取時不接手拖曳捲動。註記上的有效長按由物件選單處理；空白／原生 PDF 文字的長按交給瀏覽器。實際 Android 原生選取、慣性體驗及觸控兼容性仍須驗收。

第二指先取消未提交的筆畫、擦除、移動、縮放控制點、旋轉或圈選預覽；不保存草稿、不復原已存內容。文字／屬性草稿開啟、載入或保存中不啟動新的 pinch。兩指期間只對 page-stack（canvas、text layer、搜尋高光、註記、選框）套共同 transform；結束才更新共享 zoom，手動上下限 25%～400%。自動適配仍依實際視窗計算，捏合後改為手動。

錨點保存頁碼、頁面上的正規化座標及最新兩指中心。跨頁與頁縫選最近頁面，平手取文件順序較前頁；手勢中不換頁。新 PageView 的 scale 到位後才調 scroll，避免用舊尺寸消耗錨點；原 PDF 旋轉和 App 旋轉仍由原 pageMatrix 處理。搜尋同一個命中只初次定位，不因完成捏合後重繪再次拉回搜尋位置。

第一指離開後擋住剩餘手指，直到全數釋放；第三指、pointercancel、失去 capture、失焦或切工具取消。表單、面板、浮層不進文件手勢；控制點可被第二指接手，但不啟動物件長按。長按採 500ms、移動門檻 8 CSS px，與拖曳門檻相同；成功後消耗原 pointerup 及後續 click，新一次 pointerdown 才恢復命令點擊。筆刷一秒拉直流程不變。

## 版面與動畫

刪除 v006～v009 互相覆寫的面板／閱讀布局規則，合併成單一規則區。手机開合不呼叫 remember 或重新 fit；按鈕之外沒有 44px 透明占位。桌面以一次 margin 結算加 reader FLIP 預覽補償外觀，動畫期間暫停 fit/restore，結束才重新計算一次適配。背景跟隨 dock 的 CSS transform，快速反向沿用 CSS transition，舊完成計時取消；reduce 即刻切換。

共用側欄包括屬性、圖片與頁面；搜尋使用自己的整個外殼 SlideRegion，設定 Disclosure 延續自身區塊動畫；浮動選單整個卡片 useSlide。文字、去背 Dialog 仍採原生 top layer，不套用側欄動畫。實際中途影格、桌面錨點與最後一幀品質不能由這些程式結構保證，列入待驗收。

## 群組資料、相容與合併

`Annotation.group = {id, members}`。成員 ID 排序、無重複、含自己；每個成員保存同一份描述，群組 ID 僅在文件範圍解讀。群組不是新 kind，避免將群組當作可繪製假物件。新群組至少兩件、同頁、最多 10,000 件、每物件一組、不巢狀；重新組合先展開完整聯集，使用新群組 ID，舊關係留在歷史。

代價是成員清單重複儲存，對大群組／長歷史較耗空間。驗證限制單份歷史群組成員引用總數 1,000,000，並保留 200,000 操作、150 MiB 存檔等既有上限。引用必須是歷史中存在的註記物件且具有同頁版本，群組描述格式／排序／自含／重複均驗證。平面物件 ID 引用沒有群組巢狀循環；操作 parents 仍完整檢查同物件 DAG。

第一次保存群組升文件 format 6；解除不降版。沒有引入新語意的舊檔不改格式或歷史。IndexedDB 升至 8、不刪 store 或資料，既有連線收到 blocking 關閉；舊版不能以較低 DB 版本重開。format 5 舊客戶端明確拒絕群組檔。所有同步裝置需更新；不提供降版流程。

建立、解除、移動、缩放、旋轉、刪除及圖層批次均保存完整 expected heads；必要的未改動成員也作 guard 與同批歷史。所有成員先檢查才構造操作，IndexedDB 交易內再次檢查 heads 和整體會員一致性，之後一次提交文件／資產。儲存失敗重試保留 guard，不把過期批次變成無條件 merge；過期操作被明確拒絕。正常群組操作是一筆 undo/redo，群組／解除本身不改幾何、asset、points、文字或 layer。

跨裝置仍是操作 ID 聯集，不假設交易可跨装置同步。groupState 收集所有目前 heads 的成員主張：有多 head、成員缺失、不同描述、跨頁或競爭群組時，連通的相關群組整組 blocked。未衝突成員仍可顯示，不能從正常選取／移動流程排除衝突成員後繼續編輯剩餘部分。合併 PDF 也要求先處理群組問題；工作存檔保留全部版本。

衝突管理列出問題群組與成員；先用原候選預覽選各物件版本，再重新檢查關係。若仍不一致，明確「保留物件並解除不一致的群組」會對連通集合寫入無 group 的新版本，保留位置及已選版本；既有多 head 必須先處理，不自動挑版本。修復交易對完整集合再次驗證；之後可回編輯器重建群組。這是管理修復，不混入編輯器 session 的 undo stack，原因果歷史仍保留。

若只剩一個有效成員，也保留原主張並列為待修復；本版採較保守的整組暫停策略，不在讀取時偷偷解除或復活成員。`.pdfnote`、duplicate、Drive snapshot 都沿用完整 operations，因此群組隨檔保存，副本 ID 不同、不會跨文件牽動。
