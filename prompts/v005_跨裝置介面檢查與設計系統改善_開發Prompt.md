# v005 — 跨裝置介面檢查與設計系統改善

日期：2026-09-18。基線：App 0.4.0、[v004 規劃](v004_文字方向版面與多物件選取_開發Prompt.md)。狀態：完成靜態介面檢查及改善規劃，尚未實作本版。

## 1. 檢查方式與界線

依使用者指定，讀取並使用以下三個技能：

- [frontend-design](../.agents/skills/frontend-design/SKILL.md)：檢查頁面結構、資訊層級及操作流程。
- [responsive-layout](../.agents/skills/responsive-layout/SKILL.md)：檢查桌面、窄視窗、手機及橫向使用的適應方式。
- [design-system-architect](../.agents/skills/design-system-architect/SKILL.md)：檢查共用元件、字級、間距、色彩及互動狀態的一致性。

檢查涵蓋文件庫、資料夾、已刪除文件、編輯器、物件屬性、衝突管理、同步與設定，以及對話框／提示。閱讀目前 JSX、CSS、頁面預覽程式、v004 設計與驗收紀錄，另依 CSS 中的不透明色值計算部分文字對比。

依 [AGENTS.md](../AGENTS.md)，本次未啟動 App、網站服務或 App 瀏覽器畫面，未操作真機，未執行測試或建置。本文件的「確認」是程式碼可確認的結構／樣式事實；溢位、遮擋與觸控體驗等結果若未實際量測，均列為風險，不能視為已重現的畫面錯誤。v004 原有測試結果不等於本版介面驗收結果。

本次使用者授權的是檢查與整理 prompt。以下版面、斷點、字級及操作設計是改善建議，不冒稱使用者已逐項確認，未改動 App。

## 2. 已有成果，應保留

- 桌面大於 900 CSS px 時，編輯器已採 `minmax(0,1fr) 264px` 固定雙欄；閱讀容器已有 `min-width:0` 與寬度觀察。不要再次將「新增固定屬性欄」列成未完成工作。
- 900 CSS px 以下已提供屬性欄開關，手機主導覽已轉為底部導覽；問題在完整性與空間安排，不是完全沒有響應式設計。
- v004 已有點選、方框與自由圈選、批次操作、共同屬性及混合值處理。
- 工具模式按鈕已有 `aria-label`／`aria-pressed`，多數欄位已有標籤，錯誤提示已有 `role="alert"`；應補缺口而非全部重建。
- 保留目前米白、深綠與簡潔閱讀風格、既有 Lucide 圖示及本機字型，不另引入付費 UI 套件、外部字型或與筆記無關的裝飾功能。

## 4. 建議頁面配置與操作流程

### 4.1 文件庫、資料夾與已刪除文件

- 桌面保留左導覽，主區依序為標題與建立入口、目前路徑與搜尋、資料夾導覽、文件清單。避免多個同等權重的大型匯入按鈕同時競爭注意力。
- 手機保留目前三個主要底部目的地，不為了回收區擠成過密導覽；在文件庫的可見管理入口提供「已刪除文件」。從刪除提示也可連至該區。
- 空文件庫保留簡短引導，提供「匯入」與「新建空白文件」；已有文件時縮短歡迎區。不新增強制 onboarding。
- 資料夾清單可收合；窄版縮排上限建議 32～48px，實際樹深與父子關係保持不變。以麵包屑或完整路徑補足資訊，不將資料結構扁平化。
- 卡片保留縮圖、可辨識名稱、頁數與必要狀態。手機可用兩行名稱；完整名稱可由開啟／管理操作取得，不能只靠滑鼠 hover。
- 搜尋在窄版占完整一列，說明目前搜尋範圍；小寬度改單欄，空搜尋結果提供清除搜尋操作。
- 回收區以還原／查看為主要操作，避免仍展示大量建立、匯入與資料夾管理控件，造成與一般文件庫混淆。保留已刪除文件的匯出及必要分類功能。

### 4.2 編輯器與屬性

- 桌面保留 v004 的固定屬性欄、閱讀錨點與獨立捲動。工具列分成工具模式、當前工具設定、歷程操作，避免常駐不相關設定。
- 手機第一列放返回、截斷文件名稱、保存狀態與匯出入口；下一列提供主要工具。工具列必要時可有明確提示的局部水平捲動，但整頁不得因工具過寬而橫向溢出。
- 顏色／粗細僅在適用工具下顯示；橡皮擦直徑僅在橡皮擦模式顯示；點選／方框／自由選取僅在選取模式顯示。隱藏設定不能重設先前工具參數。
- 搜尋預設可收合，展開後移動焦點到搜尋框；頁碼與閱讀切換保持容易操作。展示方向、旋轉等次要選項可收入頁面設定。
- 手機屬性建議採有明確標題、關閉與套用操作的抽屜，面板內可獨立捲動；短螢幕可切全高編輯表單。若採模態抽屜，背景不可互動且焦點須圈限；桌面側欄為非模態，不能圈限焦點。
- 面板未套用的值沿用 v004 暫存／版本檢查語意，不因外觀重構變成自動儲存，也不能關閉即偷偷套用。定義有變更時的關閉處理，例如保留暫存並顯示未套用狀態；若變更選取會丟棄暫存，先清楚提示。
- Esc 應先處理最上層對話框／抽屜，再處理未完成手勢或選取；表單輸入中 Delete、復原等不能觸發背景筆記操作。
- 保留明確「閱讀」模式，手指須可切回捲動；不承諾未實作的雙指編輯手勢。旋轉控制點與移動把手可擴大透明命中區，但不能改變物件座標或畫進匯出 PDF。

### 4.3 衝突與同步設定

- 桌面維持清單＋預覽；手機可採清單／詳情兩步，具返回清單、目前物件名稱、頁碼、版本時間及來源裝置。長名稱與大量版本不撐出視窗。
- 分開標示「目前查看版本」與「已決定保留版本」；先預覽再選擇，不因切換 tab 自動解決衝突。刪除候選須清楚標示。
- 物件衝突與分類衝突採一致的版本按鈕、選取標記、保存中與失敗狀態，避免一種列表只有顏色、另一種另有提示。既有版本保留及同步規則不改。
- 同步設定先顯示本機保存、連線授權及同步狀態；離線可用不等於已同步，不能共用一個模糊的成功綠點。
- OAuth 首次設定入口保留，將技術欄位與說明集中到「進階連線設定」。說明可離線閱讀；不要把本機 Markdown 路徑當成使用者一定能開啟的說明連結。
- 安裝、離線快取、更新、本機資料保留各自有明確狀態和動作，保留原有資料保護說明。產品文案可寫「此版本尚不支援 Word 轉換」，不寫「第七版授權延後」。

## 5. 響應式與設計系統建議

以下數值為本專案可調整的設計目標，不是宣稱整體符合某項標準。

| 項目 | 建議 |
| --- | --- |
| 版面策略 | 以內容可用空間決定切換；先保留 760px 主導覽及 900px 屬性欄的不同職責，確認 761～900px 中間範圍，避免改一個全域斷點造成退化。 |
| 手機／窄版 | 主內容左右 12～16px；卡片寬度不足以閱讀時改一欄；大型文字／短高度時優先收合次要控件，不能縮小所有字來硬塞。 |
| 文字 | 一般內容建議 14～16px，次要文字 12～14px，標題依層級約 18／24／32px；8～10px 不再承載必要狀態或操作說明。允許使用者文字放大。 |
| 觸控 | 常用操作目標建議至少 44×44 CSS px；小圖示可維持 16～20px 外觀，以 padding／透明命中區擴大，並避免命中區互相重疊。 |
| 色彩 | 建立背景、表面、主要／次要文字、分隔線、品牌、危險、警告、成功、焦點及選取 tokens。一般資訊文字與實際背景對比目標至少 4.5:1，選取除顏色外另有框線、標記或文字。 |
| 間距／形狀 | 採 4／8／12／16／24／32 的間距尺度及少量圓角／陰影層級；延續既有閱讀風格，不全面換主題。 |
| 視窗高度 | 保留動態視窗單位，補面板與對話框可用高度處理；依實際需要處理軟鍵盤及安全區，不假設 `100dvh` 單獨解決所有鍵盤情境。 |
| 層級 | 定義導覽、一般浮層、抽屜、模態、通知的層級和互動順序。安全區 padding 依實際生效條件設置並驗證，不只加一行 CSS 宣稱完成。 |
| 動畫 | 以短暫狀態回饋為主；減少動態效果偏好下仍保留文字式忙碌提示，不依靠持續旋轉辨識進度。 |

優先共用元件：`Button`／`IconButton`、`Dialog`、`Drawer`、`Field`、`StatusBadge`、`EmptyState`。採用時先列出實際重複用例，不打造用不到的完整元件框架，也不預設新增 UI 依賴。

- Button 明確區分主要、次要、低強調、危險、停用、忙碌及選取狀態；IconButton 必須具可存取名稱。
- Field 統一標籤、說明、錯誤、單位及混合值；保留多選「多個值」而非填入假預設。
- Dialog 統一一般取消／關閉行為；儲存失敗救援視窗需獨立關閉政策，不能新增 Esc 或點遮罩直接丟棄未存資料。
- Toast 錯誤可讀且可關閉，長內容換行；不要蓋住鍵盤上方的主要操作。背景忙碌條不可遮住返回或表單標題。
- CSS 改成清楚分區、tokens 與元件規則，移除被後段覆寫的過時宣告；對 PDF.js 文字層及註記 SVG 的樣式變動採最小範圍。

## 6. 建議實作順序與驗收

1. 先補 U01、U07、U08 的功能入口與狀態缺口，建立對話框與抽屜行為規則。
2. 調整編輯器工具資訊層級、短高度及軟鍵盤流程，保留桌面固定欄與閱讀錨點。
3. 完成文件庫長名稱、深層資料夾、手機搜尋與回收區配置。
4. 套用有限共用元件及 tokens，整理 CSS，最後整合衝突／同步設定的一致性。

各步可沿用現有元件，不要求改寫資料層。若更新套件或依賴，先證明既有程式無法滿足需求；不為介面重構更動資料格式、同步協定、網站 origin 或啟停機制。
