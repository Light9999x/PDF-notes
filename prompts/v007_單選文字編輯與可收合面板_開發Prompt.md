## 1. 已確認更動

1. 單獨選取文字框時，可以進行文字內容編輯。
2. 右側預留區域改為可收合的面板，預設展開。
3. 頁面縮放除了「適合寬度」，新增可完整放下目前一張頁面的「適合整頁」。
4. 所有繪圖筆刷畫出接近直線的線條後，保持按下並長按約 1 秒，轉為起點至準心的直線；隨準心改變方向／長度，放開後定型。

第 1 項擴充 v006 原位文字編輯入口，不要求使用者先切換文字工具；不恢復已移除的「點選選取」模式。第 2 項取代桌面面板永遠占位、窄版初始收合的行為，但仍使用右側直接操作，不恢復頂部「屬性」按鈕的二段開啟流程。

第 6 項取代 v005／v006 的獨立可收合資料夾導覽樹。此處的 Google Drive 是資料夾進出操作的參考，不要求複製其品牌外觀，也不改為直接瀏覽 Google Drive 雲端檔案。

## 3. 單選文字的編輯流程

### 使用方式與建議手勢

使用者指定的是「單選可編輯」；以下手勢是兼顧既有直接拖移的建議預設，應在後續設計紀錄標示採用方式。

- 方框或自由圈選結束後，若只選到一個文字框，立即具備編輯資格，不要求切換文字工具或彈出視窗。
- 建議在該已選文字框內短按／點擊即可原位編輯並定位游標；鍵盤 Enter／F2 可作等效入口。剛結束圈選不強制彈出手機鍵盤，避免妨礙接著拖移或縮放。
- 選取狀態下，在已選文字框內按住並移動超過門檻，仍執行拖移；沒有形成拖移才進入編輯。縮放／旋轉控制點優先，不能一碰到框就立刻開 textarea 攔截整個手勢。
- 這個點擊只適用於「已單獨選取的文字框」；點未選物件仍遵守 v006 方框／自由選取規則，不新增 point 模式或短手勢回退。
- 多選（即使全是文字）不自動開某一個文字的內容編輯器；仍保留共同屬性、移動、縮放、旋轉與 Delete。單選圖片／筆跡亦不顯示文字編輯入口。
- 已進入文字編輯後，拖曳文字內容是選字，不再拖移物件；先完成或取消文字編輯，再操作物件控制點。游標、文字反白及輸入不影響 PDF 底稿文字選取隔離。
- 編輯完成或取消後回到選取模式並保留該物件選取，方便接著拖移、縮放、旋轉；文字工具既有「空白新增、點既有文字編輯」流程維持。

### 保存、草稿及焦點

- 更新原文字框 ID，不建立複製物件；位置、尺寸、角度、方向及樣式除使用者明確修改外保持不變。
- 沿用 v006：Enter 換行，Ctrl／Cmd+Enter 完成，Esc 取消本次未提交編輯；中文組字過程不提前完成。Delete 在文字編輯中僅刪字，不刪物件。
- 一次內容編輯為一次可復原操作；沒有內容變動則不新增操作紀錄。使用 expected heads 保存，遠端版本變動或寫入失敗時保留草稿及錯誤提示，不自動覆寫。
- 側欄文字草稿與原位草稿須有唯一有效來源。若側欄尚未套用，進入原位編輯前沿用現有套用／捨棄保護或轉移同份草稿；禁止把兩份不同內容先後寫回同一物件。
- 開始原位編輯前以 object ID 重新確認目前單一選取及版本，不用可能命中別的重疊文字的座標重新猜測目標。
- 收合面板不應提交或清空原位文字。若按收合按鈕造成 textarea blur，須辨識這是面板操作，保留本次文字編輯與游標；組字未完成時更不可強制提交。
- 失敗救援、離開文件提示、正在編輯頁面保持渲染、旋轉／縮放座標與存檔／PDF 匯出一致性沿用 v006。

## 4. 預設展開、可收合的右側面板

### 建議狀態規則

| 情境 | 預期行為 |
| --- | --- |
| 開啟文件進入編輯器 | 桌面及手機預設展開，無選取時顯示簡短提示。 |
| 使用者收合 | 隱藏內容並釋放閱讀寬度，只留右側可辨識的展開控制。 |
| 使用者展開 | 一次操作恢復原面板內容、未套用輸入與合理捲動位置。 |
| 同一文件內切工具／變更選取 | 更新面板內容；建議尊重手動收合狀態，不反覆強制展開。 |
| 明確按「圖片」工具 | 這是開啟圖片頁面的要求，展開面板並顯示圖片庫，沿用 v006。 |
| 改變視窗寬度／方向 | 保留使用者當次開合狀態，調整排版，不因跨斷點就改成初始值。 |
| 離開再重新開啟文件 | 建議重新以展開開始，符合「預設展開」；本版不新增跨工作階段記住收合狀態。 |
| 圖片拖出／點選放置 | 可暫時讓出空間；結束或取消後恢復動作前的開合狀態，不把暫時隱藏當成手動收合偏好。 |

其中「尊重當次手動收合」「再次開文件展開」及拖放後恢復，是規劃預設，不是使用者另行指定的持久化規則。

### 版面與資料保護

- 將收合／展開控制放在面板邊緣或標題處，桌面與手機都可操作。採簡單箭頭圖示、明確可存取名稱、`aria-expanded` 與內容關聯，不在上方加新的屬性列。
- 桌面展開占用右欄，收合後閱讀區使用釋出的寬度；不能只藏內容卻留下整條 264px 空白。屬性與圖片共用同一開合狀態，不因切內容抖動欄寬。
- 面板收合不清除選取、不自動套用／捨棄屬性、不刪圖片、不改文件內容、不觸發同步或新增復原操作。需要隱藏的內容不可留在 Tab 順序中；焦點若正在被收合的面板內，移到側邊展開控制。
- 原位文字框屬於閱讀區，不能因側欄收合而被卸載、移回側欄或搶走輸入焦點。避免因重新掛載 PropertiesPanel 清掉未套用草稿。
- 符合寬度模式：依新的閱讀區可用寬度重算並保留當前頁面／閱讀錨點。手動縮放模式：保留縮放倍率，只調整可用區，不自行切回符合寬度。防止縮放觀察與面板動畫形成反覆重排。
- 手機空間不足可沿用非模態側邊覆蓋形式，但初始仍展開；收合控制必須可達、可一次讓出頁面。不可因預設展開而封鎖背景圖片放置，或逼使用者回頂部找開關。
- 視覺沿用 v006 精簡原則：同一時間一組開合控制、無額外常駐教學；觸控尺寸、鍵盤焦點、短視窗及軟鍵盤仍需可用。

## 5. 新增「適合整頁」縮放

- 在目前縮放／頁面設定中，將「適合整頁」與「適合寬度」放在同一層，可直接選擇且有目前模式標記。不新增獨立對話框或常駐說明列。
- 「整頁」指目前作用頁的一張 PDF 紙張，不是一次顯示整份文件，也不改 PDF 紙張尺寸、物件尺寸或連續閱讀的展示方向。
- 以當前頁經原生／App 旋轉後、scale=1 的可視尺寸 `pageWidth`、`pageHeight` 計算：`zoom = min(availableWidth / pageWidth, availableHeight / pageHeight)`。
- 可用空間以實際閱讀容器為準，扣除內距、捲軸及必要控制點空間；工具列、搜尋列、頁尾與展開右欄已占用的部分不可算入。不要直接使用整個視窗寬高，亦不要重複扣除已由布局排除的側欄。
- 作用頁四邊須完整落在未被面板遮住的閱讀區，水平置中，垂直在可行範圍置中；連續閱讀可調整捲動位置及首尾留白，不必隱藏其他頁面或改成單頁閱讀。
- 清楚保存縮放模式：手動、適合寬度、適合整頁。按放大／縮小或手動改倍率後進入手動模式；重新選適合整頁後恢復自動計算。Ctrl／手勢縮放若由 App 接管，亦須遵守同一規則。
- 適合整頁模式下，面板開合、工具／搜尋列高度變動、視窗大小／方向或頁面旋轉變動時，重新計算並保持目前作用頁可見；適合寬度只依可用寬度重算，手動模式保持原倍率。
- 建議跳到另一頁時，以新頁尺寸重新適配，支援同文件混合紙張大小／橫直方向。自由捲動跨頁時，在作用頁穩定後才重算，保存錨點並防止重新縮放引發作用頁來回切換。
- 比例需有限且大於零；容器尚未完成量測或尺寸為零時等待有效值，不寫入 Infinity／NaN。非常大的頁面可能需要低於既有手動下限的比例，不能直接套用固定 25% 下限而宣稱整頁可見；適配模式需採可實際容納整頁的正值。
- 手機右側覆蓋面板若未縮小容器，須另外評估真正未遮擋區，讓整頁落在可見區域；不能只量到容器寬度就把被側欄蓋住的部分當作完整顯示。不得為了符合整頁偷偷收合使用者展開的面板。
- 與正在進行的拖移／縮放／旋轉或文字輸入協調：手勢期間凍結所需座標，結束後再適配；重排不能提交文字草稿或改變物件資料。縮放只屬於閱讀狀態，不進文件操作歷史、同步註記或匯出 PDF。

## 6. 筆刷長按拉直

### 確認流程

- 適用所有繪圖筆刷，現階段包含畫筆、螢光筆；橡皮擦、選取、文字及圖片工具不屬於筆刷，不啟用此功能。
- 使用者按下並畫出接近直線的線條後，保持按下約 1 秒，將本次尚未提交的筆跡轉為「本次起點 → 目前準心」的單一直線。
- 進入直線預覽後仍維持按住，準心移動時持續更新終點；起點固定，可以自由改方向、拉長或縮短，直到放開才保存最後方向與長度。不吸附水平／垂直或固定角度，除非後續另外要求。
- 保留原工具的顏色、實際直徑、透明度與目前已支援的筆刷外觀。只改本次筆跡，不掃描或修改先前已保存的曲線。
- 放開時保存一個普通可編輯筆跡物件，直線可用起終點表示；仍可選取、移動、縮放、旋轉、擦除、復原、同步及匯出，不新增不可編輯的特殊圖層。

### 避免誤觸的建議預設

使用者指定的是「近直線＋長按約 1 秒」；以下是實作可採用的量化預設，需記錄並待實際手感驗證，不能當成已確認數值。

- 「長按」解讀為畫出線段後，指標仍按下並在端點附近停留約 1000ms；不是從 pointerdown 起算滿 1 秒就強制拉直，持續慢畫也不應自動觸發。
- 先確認起終點距離達最小值，再判定近直線。建議最小長度 20 CSS px；排除原地按住的點、極短線、明顯弧線、迴圈及折返筆跡。
- 近直線可結合兩項幾何條件：有效軌跡相對起終點線段的最大垂直偏差，以及軌跡總長／起終點距離；可先採偏差不超過 `max(3px, 線長×4%)`、長度比不超過 1.15，再依實測調整。計算前排除微小抖動，避免不同裝置取樣頻率主導結果。
- 幾何門檻先轉到畫面 CSS px 評估，筆跡資料仍保存頁面座標；同樣手勢在不同 PDF zoom／DPR 下應有一致感受，不以筆刷粗細直接放寬成容易把曲線拉直。
- 端點停留容差建議半徑 3 CSS px：計時錨點固定於本次停留開始位置，超出即重設計時，不能每個小步都移動錨點而讓緩慢漂移累計成長按。
- 計時結束時再次驗證同一手勢、同一工具／指標仍按下且軌跡近直線。沒有新的 pointermove 也應能到時轉直線，不能只在下一個 move 事件檢查時間。
- 進入直線預覽後不再要求端點停留，也不因新的方向與原路徑不同就退回自由筆跡；放開或取消之前一直由起點連到目前準心。
- 若尚未滿 1 秒就放開，沿用一般自由筆跡保存；不符合近直線時也維持自由筆跡，不中斷使用者書寫。

### 指標、取消與保存

- 支援滑鼠、手指及未來觸控筆，依 pointerId 維持同一條筆跡；不要把長按導向瀏覽器文字選取或系統長按選單。只在筆跡畫布的繪圖手勢隔離相關預設行為，閱讀及表單仍正常。
- 指標到起始頁面外時，依既有繪圖邊界政策限制終點，建議裁切至同頁邊界；不可在另一頁突然新建第二條直線或跳動座標。應能接收頁外放開，正確結束 pointer capture。
- Esc、pointercancel、失焦、切工具、切文件或元件卸載時，清除計時與預覽；沿用未完成筆跡取消政策，不在稍後的 timer callback 突然新增直線。
- 每次手勢使用識別值或等效保護避免舊計時器影響下一條線；pointerup 與計時同時發生時只提交一次。進入直線預覽前的自由軌跡只作草稿，不另存成第二個物件。
- 一次放開對應一次建立與復原操作，包含本地寫入失敗處理。離線、`.pdfnote`、Google Drive 與 PDF 匯出沿用既有筆跡資料流程；不把停留計時或準心狀態寫進文件。
- 在畫面上直接以「筆跡變直」作回饋即可，不新增彈窗、工具列或常駐長篇教學。原十字準心與顏色／尺寸控制維持。

## 7. 圖片頁面與工具列選取狀態同步

- 按工具列「插入圖片」開啟右側圖片頁面後，圖片按鈕使用與其他工具一致的已選取樣式及 `aria-pressed` 等適切狀態，不只是按下瞬間的 focus／hover。
- 任何入口切到圖片頁面都應同步上方狀態；不能仍顯示畫筆、文字或選取工具是目前模式，讓使用者誤判點畫布會做什麼。
- 將「目前工具／情境」「面板是否展開」「圖片是否正在放置」「目前選取物件」分清楚；不必重建整套狀態，但不能只加一個互不連動的樣式 boolean。
- 圖片頁面開啟時，點頁面不應沿用先前畫筆意外畫線。已有圖片待放置就放置圖片，沒有待放置時維持明確且不新增筆跡的操作；既有圖片仍可選取及調整尺寸。
- 切換畫筆、選取、文字等工具時，更新上方目前工具及右側對應情境，清除圖片按鈕的已選取狀態；取消未完成的圖片放置預覽，但保留已匯入的圖片庫資產。
- 收合面板只隱藏內容，不切換目前圖片情境；展開後仍是圖片頁面，圖片按鈕仍已選取。明確切回物件屬性時再同步到對應工具／情境，不能因右側入口切換而留下圖片高亮。
- 建議圖片放置成功後仍保留圖片頁面與圖片按鈕已選取，同時選取剛放入的圖片以便縮放；「圖片物件被選取」不代表工具列一定要改亮選取工具。若採不同的完成後流程，必須兩處一起切換，不能面板留圖片卻上方顯示另一工具。
- 不新增第二組圖片頁籤或工具列。沿用簡潔、單一目前情境的外觀；內部為拖移／縮放使用的手勢狀態不應導致上方選取樣式閃動。

## 8. 文件庫直接瀏覽資料夾

### 頁面結構

- 移除獨立的「資料夾導覽」標題、展開區塊及全樹縮排清單。主內容直接顯示目前位置下的資料夾和文件，不需先展開另一區才能進資料夾。
- 建議上方依序為精簡標題與建立／匯入動作、返回及麵包屑路徑、搜尋，再來是資料夾與文件內容。資料夾可優先排列、與文件用圖示／縮圖區分；不要求新增卡片／列表切換器。
- 建議根位置命名為「我的文件」，顯示頂層資料夾及未分類文件；進資料夾只顯示其直接子資料夾與直接所屬文件，不把全部後代或全庫文件攤在每一層。
- 根位置與現有 `scope='all'` 語意不同，需明確區分。目前「全部文件」可保留為簡短檢視選項，顯示各文件所屬路徑；不要將根位置標成全部文件卻暗中漏掉子層文件。
- 現有「未分類」如仍保留，可作簡短篩選，不建立假的未分類資料夾或改寫其 folderId。原本無資料夾歸屬的文件在根位置可見。
- 手機與桌面都用相同階層概念；窄版路徑太長可縮略中間層，但根與目前資料夾須可辨認，隱藏祖先可由可操作選單取得，不依賴 hover。

### 進入、返回與位置恢復

- 建議桌面單擊／手機單點資料夾即可進入，Enter 可開啟；拖曳移動不誤觸開啟，保留既有 suppressDragClick 或等效處理。若採雙擊桌面模式，需明確一致且手機仍可單點。
- 「返回」回到前一個瀏覽位置；麵包屑可直接進入任意祖先或根位置。返回歷程與父資料夾是不同概念，不能從搜尋／全部文件進資料夾後，返回卻只硬跳父層。
- 無歷程可返回時停用返回；若另提供「上一層」，根位置停用，使用正確父 ID。歷程至少保存位置、搜尋字串及捲動位置，進文件閱讀後返回文件庫仍回原資料夾及合理位置，不每次回全部文件。
- 按目前層級搜尋時，建議同時比對直接子資料夾名稱與文件名稱；搜尋範圍清楚標示。全庫搜尋如保留應屬明確的全部文件檢視，不默默改成本輪的新跨層搜尋功能。
- 空資料夾顯示「此資料夾沒有內容」及可用建立／匯入操作，不顯示整個 App 的首次使用引導。只有子資料夾而沒有文件時，不可誤判為空頁。
- 同步造成目前資料夾改名、移動、刪除或歷程目標失效時，以 ID 重算路徑；必要時回最近有效祖先或根位置並簡短提示。不要循環返回失效資料夾、產生無限麵包屑或讓文件消失。

### 管理與相容

- 新增資料夾、新建空白文件、匯入檔案預設位於目前資料夾；根位置則建立頂層資料夾／未分類文件。原本全部文件／回收區等特殊檢視須維持明確目的地，不把檢視識別值當 folderId 寫入。
- 文件／資料夾更多選單仍能改名、移動及刪除，手機不依賴拖曳。桌面仍可拖入可見的資料夾，移回祖先／根層可用麵包屑放置目標或既有移動對話框，不復活獨立導覽樹。
- 防止把資料夾移入自己或後代；沿用同名、空資料夾刪除限制、已刪除文件還原、階層異常及分類衝突保護。這次只改瀏覽方式，不自行加入遞迴刪除或複製資料。
- 名稱／父層衝突、孤立資料夾及分類異常依現有安全回退呈現，保留衝突入口和提示，不因只列直接子層就隱藏異常內容。階層解析必須有循環保護。
- 瀏覽位置、歷程與搜尋不寫成文件分類變更，不觸發不必要同步。保留現有資料夾 ID、父 ID、文件歸屬與操作紀錄，無需為外觀重排搬移文件或更換同步格式。
- 沿用 v006 的簡潔設計：不要同時保留舊導覽樹、新路徑列和第二份資料夾清單，也不為模仿 Google Drive 加入分享、帳號切換或額外雲端功能。

以上根位置呈現、單擊進入、搜尋及歷程細節是規劃預設，後續應記錄採用方式；已確認需求是直接顯示資料夾、能進出與返回，並移除原導覽區塊。
