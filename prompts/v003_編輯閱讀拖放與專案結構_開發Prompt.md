# PDFnote v003：編輯、閱讀、拖放與專案結構

Prompt 版本：v003  
整理日期：2026-09-18  
前置：[v001 核心規劃](v001_核心功能規劃與開發Prompt.md)、[v002 資料夾與空白文件](v002_資料夾與空白文件_開發Prompt.md)

## 1. 基線與本輪需求

檢視目前程式及文件可見，App 已依 v002 更新為 0.2.0，具備單層資料夾與空白 PDF 建立。既有自動化測試紀錄不代表使用者已實測，也不代表本輪新功能已完成。實作前需重新確認當時程式，沿用既有 PWA、離線保存、Google Drive 隱藏區、版本衝突與 `.pdfnote` 機制，不重建 App。

使用者本輪指定：

1. 橡皮擦可按住操作，刪除作用範圍內的筆跡物件；準心改為圓圈，只有筆刷使用十字。
2. 文字框可水平或垂直排字，並可自由調整角度；預設水平往右。
3. 調整檔案和資料夾歸屬時，可直接用滑鼠拖曳。
4. PDF 預設垂直展示，可用滾輪在頁面間移動；也可切換水平展示。
5. Prompt 資料夾與應用程式分開，將應用程式集中到一個資料夾。
6. 橡皮擦大小可像筆刷一樣調整，調整時滑鼠圓形準心大小也跟著改變。

## 2. 需求解讀與建議預設

| 項目 | 規劃解讀／建議 | 性質 |
| --- | --- | --- |
| 橡皮擦 | 刪除命中的整個筆跡物件，不切割成殘留筆段；按住拖過多筆即可連續刪除。 | 沿用使用者的「筆跡物件」敘述。 |
| 擦除對象 | 預設包含畫筆與螢光筆筆跡，排除文字框、圖片及 PDF 本身內容。 | 筆跡類型範圍為建議預設。 |
| 橡皮擦大小 | 提供大小控制，準心直徑與實際擦除範圍同時改變。 | 使用者已確認；具體單位及控制元件由實作設計。 |
| 擦除設定與復原 | 建議橡皮擦與筆刷分開保存大小；一次按下到放開為一組復原操作。 | 操作細節建議，尚非使用者明確指定。 |
| 文字直排 | 建議採中文直排：字由上到下，換欄由右到左。英數及標點規則在實作時訂定並測試。 | 垂直排字方向的建議預設。 |
| 文字角度 | 水平／垂直是排版屬性，旋轉是另一個屬性；預設水平向右、0°。 | 配合兩種獨立需求的解讀。 |
| 資料夾拖放 | 「檔案和資料夾歸屬」解讀為文件移入／移出資料夾，以及資料夾移入另一資料夾或根目錄。 | 本輪範圍解讀，擴充 v002 的單層預設；不是純圖示排序。 |
| PDF 展示 | 預設多頁由上到下連續排列；水平模式由左到右連續排列。 | 展示方向不改變 PDF 頁面尺寸、旋轉或內容順序。 |
| 閱讀偏好 | 建議依裝置、依文件記住展示方向與閱讀位置，不作為會產生內容衝突的文件變更。 | 儲存偏好建議。 |
| 專案目錄 | 根目錄保留 `prompts/`，新增 `app/` 集中應用程式及其開發文件。 | 分離已確認，資料夾名稱 `app` 為本規劃採用的命名。 |

上述解讀與預設不得回溯描述成使用者逐項指定；若使用者後續調整，以新指示為準。

## 3. 範圍橡皮擦與工具準心

### 使用流程

- 選擇橡皮擦，在可編輯頁面上顯示圓形範圍指示；圓圈不含十字，離開頁面或切換工具時隱藏。
- 工具列提供橡皮擦大小調整，操作方式與筆刷大小控制一致或相近；改變大小後，圓形準心及實際擦除範圍立即同步更新。不可只放大圖示卻仍沿用原命中半徑。
- 建議筆刷粗細與橡皮擦大小各自記住，切換工具不互相改寫；顯示的大小單位與直徑／半徑意義要一致，值須限制為有效正數。
- 按住滑鼠左鍵並拖曳時，圓形範圍沿移動路徑持續偵測筆跡，命中的所有有效筆跡物件都刪除，不只最上層或滑鼠事件直接指到的一筆。
- 原地按下可擦除範圍內筆跡；未按下只預覽範圍，不刪除。放開、取消、失焦或切換工具後立即停止。
- 畫筆 `pen` 保持十字；選取、文字、閱讀、螢光筆等其他工具不得一律沿用十字準心，使用符合操作的非十字提示。

### 命中與資料要求

- 圓圈顯示大小要與實際命中一致。建議以螢幕尺寸設定範圍，再透過各頁座標轉換計算；縮放、裝置像素比及頁面旋轉不能造成指示與實際擦除分離。
- 用筆跡的實際線段、線寬及端點判斷相交，不只看外接矩形。快速拖曳需涵蓋相鄰指標位置之間掃過的區域，避免漏掉細筆跡。
- 單次手勢內同一物件只刪除一次；重疊的多筆可全部命中。文字、圖片與 PDF 文字／底圖不能因擦除經過而刪除。
- 沿用刪除操作與版本紀錄，不直接移除歷史資料。對已有未解決衝突的物件保留候選版本並提示先處理，不替使用者選版後刪除。
- 建議一組復原能還原本次手勢成功刪除的多筆，再一次重做；若其間收到遠端更動，沿用保護新版本的規則，不能把未見的變更覆蓋掉。
- 定義手勢取消時已成功保存部分的處理；至少必須停止後續刪除、保持 UI 與本機資料一致且可追溯，不留持續擦除狀態。
- 多頁模式下依被觸及頁面計算座標。頁面間隙不命中，不能把第一頁的座標套到其他頁面；觸控模式維持繪圖與捲動的區分。

## 4. 文字方向與自由旋轉

- 新增文字預設由左往右的水平排版、角度 0°。選取文字框後提供水平／垂直切換。
- 垂直排字是實際字元排列及換欄，不是把整段水平文字旋轉 90°冒充直排。
- 提供自由角度調整，不能只有 90°切換。建議提供旋轉控制點及可直接輸入的角度欄位，支援重設 0°；角度單位、正方向與旋轉中心明確一致。
- 建議以文字框中心旋轉；文字框寬高仍定義在自己的未旋轉座標系。拖曳、縮放、選取邊框及命中範圍要跟著旋轉結果更新。
- 水平／垂直排版與旋轉可組合；切換排版不自動清除角度，也不修改文字內容。
- 在實作時明確處理換行、文字框裁切、字距／行距、中文標點及混合英數，至少有中英混排與多行的代表性驗證案例。排版細節不必全部新增成使用者設定。
- 方向與角度隨文字物件保存、同步、衝突預覽與 `.pdfnote` 匯出／匯入。合併 PDF 必須呈現相同方向、角度、位置與裁切結果，不能只改編輯器 CSS。
- 舊文字物件沒有新欄位時，以水平向右、0°讀取。不要為了補預設值而改寫既有不可變操作，造成同一操作 ID 的內容不一致。
- 新欄位的型別、合法值、非有限角度與格式相容策略需納入驗證。若舊程式無法理解新資料，採明確版本策略，不能宣稱可無損往返後再默默丟掉方向或角度。

## 5. 文件與資料夾拖放歸屬

### 互動與邊界

- 文件可拖到目標資料夾，也可拖到「未分類」以移出資料夾。
- 資料夾可拖到另一資料夾成為子資料夾，或拖到明確的「資料夾根目錄」區域移回最外層。
- 「全部文件」是檢視，不是歸屬目的地；不要把它與未分類或根目錄混為一談。
- 按住移動超過合理拖曳距離後才開始拖放，避免普通點擊誤搬移；拖曳結束不要又觸發開啟文件。
- 顯示正在拖曳的項目與目的地高亮，非法目標有明確禁用提示；放到空白、放到原位置或按 Esc 取消不修改歸屬。
- 保留既有「移動到資料夾」選單，並為資料夾提供等效移動操作，供手機與不便拖曳時使用；本輪明確要求的是滑鼠拖放，不強制加入手機長按拖放。
- 文件與資料夾都使用原 ID 搬移，不複製內容、不重新產生 PDF，不遺失子層內容或筆記版本。

### 階層與同步

- v002 的單層資料夾改為可表達父資料夾的階層；舊資料夾預設在根目錄。建議提供路徑導覽或可展開的資料夾清單，使巢狀內容可找到。
- 禁止資料夾放入自己或任何子孫資料夾；名稱重複規則從全域調整為同一父層檢查，不因搬移而默默覆蓋同名資料夾。
- 文件歸屬、資料夾父層及資料夾名稱的變更應避免互相覆蓋；設計新的管理資料操作與驗證，不把分類寫成頁面註記。
- 同步兩端各自看似合法的搬移，也可能形成 A 位於 B、B 位於 A 的循環；合併後同樣要檢查階層，保留變更資料並顯示待處理衝突，不讓遞迴遍歷卡住或內容消失。
- 父資料夾被刪除、未同步或有衝突時，讓子資料夾／文件仍有可見的暫存根層、未分類或待整理入口；由使用者解決，不連帶刪除。
- 保留非空資料夾不可直接刪除的既有規則；「非空」包括子資料夾。搬移與刪除的競爭須保護所有文件內容。
- 同步重試去重，並將歸屬候選版本與階層衝突接到既有管理資料衝突介面。搬移成功、本機儲存失敗及同步待處理的狀態不可混淆。
- 單份 `.pdfnote` 仍不夾帶整個資料夾樹，沿用新匯入／副本放目前資料夾、合併不覆蓋既有分類的規則。

## 6. 垂直／水平連續 PDF 展示

- 首次開啟預設垂直連續排列多頁，滾輪可從第一頁捲到後續頁面，不能仍只替換單一頁面畫布並稱為連續展示。
- 提供「垂直展示／水平展示」控制。水平模式將頁面由左至右排列，不旋轉頁面、不改 PDF 原本直式或橫式的紙張方向。
- 保留頁碼輸入、上一頁／下一頁與文字搜尋；操作後捲動至對應頁面，而不是破壞連續排列。
- 目前頁碼跟隨主要可見頁更新。新增文字／圖片的目標頁需清楚：頁面點擊以實際頁為準；工具列直接插入時使用明確的目前作用頁。
- 水平模式建議支援水平觸控板／捲軸，並在閱讀區把一般滾輪轉成水平捲動；勿重複處理原生水平事件，不攔截 Ctrl／Cmd+滾輪的既有縮放行為或工具面板內的捲動。
- 切換展示方向、縮放、搜尋跳頁後應保持可理解的閱讀位置。建議以頁碼與頁內相對位置作為錨點，不只保存整個容器的絕對 scrollTop。
- 垂直與水平模式均記住本機閱讀位置；舊版單頁位置能合理遷移。閱讀偏好變更不產生筆記內容衝突，也不寫進 PDF 的頁面內容。
- 每頁具有自己的尺寸、裁切、旋轉、PDF 文字層及註記層；指標座標依該頁矩陣換算。不可只用目前頁矩陣處理所有可見頁。
- 編輯、擦除、選取及復原／重做要能跨頁正確定位，但一筆畫線仍屬於起始頁，不在其他頁面複製同筆路徑；頁面間隙不產生物件。
- 大型 PDF 採可見頁附近渲染或適當快取，保留頁面佔位尺寸並釋放遠頁資源；捲動不得因載入／卸載跳位，也不能卸載仍在操作中的頁面造成未保存筆跡遺失。
- 保留原文字選取、搜尋及匯出能力。頁面展示設定、工具準心、捲軸與選取框都不能被畫入分享 PDF。

## 7. 專案目錄分離、實作定位與相容性

### 目標目錄

本節為後續實作時要執行的搬移計畫，本輪建立 prompt 尚未搬動應用程式。

```text
PDF-workspace/
  README.md                 專案入口：連結規劃與 App 操作說明
  .gitignore                版本控制排除規則
  prompts/                  所有版本 prompt 與 CHANGELOG
  app/
    README.md               啟動、安裝、離線、關閉與更新說明
    GOOGLE_DRIVE_SETUP.md
    package.json
    package-lock.json
    index.html
    start-pdfnote.ps1
    src/
    public/
    scripts/
    tests/
    e2e/
    docs/
    設定檔及建置、測試、依賴目錄
```

- 將程式碼、靜態資產、npm 清單與 lockfile、TypeScript／Vite／Vitest／Playwright 設定、啟動腳本、測試及 App 文件集中於 `app/`。
- 根目錄保留規劃與專案入口；若有 `.git`、`AGENTS.md`、`.agents` 或 `.codex` 等儲存庫／工作區設定，先辨識其作用，不盲目移入 App。
- 原 App README 移到 `app/README.md` 並更新指令與相對連結；根 README 作為精簡入口，說明執行指令前進入 `app/`，並連到 `prompts/` 與 App 說明。
- `node_modules`、`.npm-cache`、`dist`、`release`、`test-results`、`playwright-report`、tsbuildinfo 等應用程式產物也歸入 `app/` 或由該處重新產生，避免根目錄殘留另一份可誤啟動的 App。先確認既有程序與檔案鎖，保留必要驗收產物，不任意刪除使用者檔案。
- 啟動腳本以自身位置找到 App，從不同工作目錄啟動都應正確。更新建置／打包腳本、測試設定、資產來源及文件連結，不能只搬 `src/`。
- 檔案系統移到 `app/` 不代表網站必須改成 `/app/` 網址。優先保留既有 origin、port 與 URL base，避免瀏覽器本機資料看似遺失、service worker 範圍變動或 OAuth 來源不符；若必須改網址，先設計資料保留與設定遷移。
- 不更改文件 ID、清空 IndexedDB 或重新生成使用者 PDF。既有離線資料與 `.pdfnote` 備份不因專案整理被刪除。
- 更新本版、舊版 prompt 導覽及 changelog 中仍作為入口使用的文件連結；歷史段落可保留原始路徑文字並註明搬移。舊 prompt 的程式定位以歷史記錄處理，不將其內容重新解讀成新版實作。

## 8. 驗收情境

1. 橡皮擦按住拖過多筆、重疊筆跡及快速掃過細線，正確刪除命中的整個筆跡；僅外接框相交但未碰到筆跡的物件不誤刪。
2. 未按下只顯示圓圈，放開／取消／失焦停止擦除；只有畫筆十字，其他工具不沿用十字。
3. 不同縮放、裝置像素比、旋轉及裁切頁面下，圓形指示與實際範圍一致，文字和圖片不被橡皮擦誤刪。
4. 擦除的保存、同步、衝突與一組復原／重做行為一致，不復活未見的遠端版本。
5. 文字預設水平向右、0°；水平／垂直搭配 0°、45°、90°及其他任意角度，移動、縮放、選取、裁切、中英混排與換行正確。
