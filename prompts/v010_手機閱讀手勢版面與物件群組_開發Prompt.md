# v010：手機閱讀手勢、版面與物件群組

整理日期：2026-09-23。原始碼基線：App **0.9.0**，目前文件 format 1～5、本機資料庫版本 7。

本輪只整理需求、靜態檢查結果及可直接使用的開發 prompt，**沒有實作這十項，也沒有啟動 App／服務／瀏覽器或更新部署**。原始碼已有 v009，但使用者回報手機版面與動畫仍不符合需求；不能以既有單元測試取代實際操作結果。執行本 prompt 時須重新確認最新程式與線上版本。

## 1. 本輪已確認需求

| 編號 | 需求 |
| --- | --- |
| 1 | 手機放大縮小只作用於文件頁面本身，工具列與整個網站介面不跟著縮放。 |
| 2 | 手機物件屬性面板不預留閱讀空間。 |
| 3 | 手機與電腦的面板收放控制只是一個按鈕，不再為它保留整排／整欄及按鈕下方空間。 |
| 4 | 減少手機工具列占用的畫面空間。 |
| 5 | 「頁面設定」整合成獨立工具，與畫筆等工具並列。 |
| 6 | **已另行確認：手機已有選取時保留目前集合；框內拖曳只移動，明確取消後才能重新選取。** |
| 7 | 已選取物件的整個外框內皆可開始移動，不必碰到物件實際內容；包含多選物件之間的空隙。 |
| 8 | 修正滑入滑出動畫，目前使用者看到只有文字滑動。 |
| 9 | 新增「建立群組」與「解除群組」，將所選物件整合成可共同操作的群組。 |
| 10 | 電腦右鍵／手機長按物件時，出現建立群組、解除群組、刪除等操作選單。 |

第 1 點的「簡報本身」在此專案指正在閱讀的 PDF／筆記紙張及附著的註記，不代表新增 PowerPoint 匯入。第 3 點指既有側面板開合控制，不是刪除上一頁／下一頁功能。未指定僅手機的第 3、5、7～10 點應涵蓋電腦及手機。

保留既有免費、離線編輯、原始檔保留、可編輯 `.pdfnote`、Drive 因果合併及衝突管理需求。保留前輪「側面板在左側、按鈕在面板外側、預設展開」；本輪改變空間占用方式，不自行改成預設收合。

## 3. 手機文件縮放與平移（第 1 點）

- 在文件閱讀區以雙指縮放文件，PDF 畫布、文字層、搜尋高光、註記及選取框對齊；外層工具列、面板、字體和按鈕尺寸保持不變。放大的是視圖，不修改物件座標、筆跡粗細、匯出尺寸或內容版本。
- 以兩指中心下的文件座標作錨點，比例依指距變化更新；兩指一起移動時可平移。頁間空隙或兩指分處不同頁時，也要有穩定的作用頁／錨點規則，避免跳頁及突然回左上角。
- 讓閱讀與編輯情境都能辨識第二根手指。建議第二指進入時取消尚未提交的單指筆跡／移動／擦除／框選預覽，切換到視圖手勢，已保存內容不回滾；雙指結束後保留選取集合。不要讓餘下的一指立即補畫、點選或提交物件變更，需全部放開再開始新編輯手勢。
- 不把多指手勢綁在只有編輯模式可接收事件的註記 SVG；涵蓋紙張、文字層及閱讀區空白。工具列／表單／彈出選單的觸控不啟動文件縮放。
- 局部配置瀏覽器原生手勢與 App 手勢，完整處理 pointerup、pointercancel、失焦、lost capture、第三根手指和切工具；明確列出閱讀單指捲動、文字選取與編輯單指手勢的保留方式。
- 不以全域 `user-scalable=no`、`maximum-scale=1`、body 全域攔截，或縮放整個 App 根節點來假裝修正。保留介面本身的無障礙放大途徑。
- 手動文件縮放退出「適合寬度／適合整頁」模式；再次選適配可恢復。與縮放按鈕共用比例、上限及保存位置邏輯，不建立第二份互相覆寫的 zoom。
- 建議手勢期間以同步視圖預覽、合併更新及取消舊渲染避免每個 pointermove 重繪所有 PDF；結束後按最終比例重繪清晰頁面。不要只放大 canvas 卻留下舊文字層或舊命中矩陣。

驗收時記錄手勢前後 PDF 尺寸、UI 控制尺寸、zoom 及 `visualViewport.scale`：應為文件比例變動、UI 尺寸穩定，不把瀏覽器 viewport 縮放誤判成文件縮放。軟鍵盤造成的 viewport 變化另行區分。

## 4. 面板與開合按鈕不占多餘空間（第 2、3 點）

### 手機

- 左側屬性／圖片／頁面工具面板以覆蓋方式開啟，不建立 grid 欄、空白排、透明占位或 cover 扣寬。開啟與收合不重新縮小／平移底下 PDF，只遮住局部內容。
- 「適合寬度／整頁」以完整閱讀容器計算，搜尋位置與頁面置中也不得因面板顯示而硬加左偏移。搜尋結果恰被面板遮住時，可提供收合／顯示結果的動作，但不能偷偷變更閱讀區大小。
- 收合後面板不攔截觸控、不留看不見的背景層、不讓隱藏內容取得焦點。面板自身長內容可捲動，事件不穿透到紙張。

### 手機及電腦共通

- 開合控制改為定位於面板邊緣的獨立小按鈕：展開時在面板外側，收合後仍可觸及。**刪除按鈕專用的整欄／整排**，其下方與周圍位置歸還閱讀區。
- 按鈕可覆蓋閱讀區，但命中範圍只限按鈕本身，不以透明滿高容器攔截整側操作。圖示、名稱、焦點及 expanded 狀態需清楚，建議至少 44×44 CSS px 觸控目標。
- 電腦展開時可繼續為面板本體預留所需寬度；收合時連本體空間一併釋出。這與手機完全覆蓋的規則區分，不刪除桌面既有可讀性設計。
- 修正不同斷點與舊 CSS 覆寫的重複規則，避免在檔案末尾持續疊加互相抵銷的宣告。

## 5. 手機精簡工具列與獨立頁面工具（第 4、5 點）

- 盤點目前常駐的標題、模式列、設定槽、頁碼、搜尋與頁尾。移走重複說明與空設定槽，保留文件名稱、保存異常、返回、匯出、常用工具和必要頁碼資訊。
- 建議預設：手機常態只保留精簡標題列及一列工具，工具過多時橫向捲動；工具參數放入同一可收合情境面板，不因選取／文字工具沒有參數而保留高空白列。正常字級可先以約 96～112 CSS px 常駐頂部區為設計目標（不含 safe area），最終依實際測量調整，不能用縮小觸控目標硬達標。
- 保留畫筆／螢光筆顏色、直徑的滑條＋純輸入，及橡皮擦大小；不要為省空間移除既有功能。工具切換保持相同模式列高度，不反覆擠動紙張。
- 「頁面」成為與閱讀、選取、畫筆、文字、圖片等並列的工具，只有一個來源狀態控制高亮與面板內容。移除另開設定列的重複入口／獨立 settingsOpen 狀態。
- 頁面工具面板集中顯示縮放、適合寬度、適合整頁、旋轉與垂直／水平展示；頁碼可保留精簡快捷入口。切到頁面工具不畫筆、不擦除、不新增文字，紙張維持閱讀與雙指手勢。
- 頁面旋轉／縮放只改視圖，保留物件、選取與未解決衝突。切工具時沿用既有未套用草稿保護；返回先前工具時保留參數。
- 搜尋可以是暫時覆蓋控制，不常駐多占一整列；聚焦、鍵盤與前後命中入口仍可用。短高度／橫向／放大字體時工具可達、閱讀區不縮到不可操作。
- 延續三個技能的簡潔、一致與自適應原則；狀態／錯誤可放精簡位置，但不得隱藏真正的儲存失敗。

## 6. 保留手機選取與框內移動（第 6、7 點）

第 6 點為使用者確認的行為，不得實作成「修正後可以任意點其他物件重選」。以下點選／拖移規則適用於手機的選取／物件操作情境；切到其他工具可保留選取紀錄，但不能讓它攔截該工具的正常操作。規則應按實際輸入／手機情境處理，不能只靠視窗窄就禁掉電腦滑鼠操作。

| 狀態／輸入 | 必要結果 |
| --- | --- |
| 手機尚無選取，點物件或框選／圈選 | 建立選取；若命中已建立群組則選整組。 |
| 手機已有選取，在框內拖曳 | 移動整個既有集合，包含框內空隙，不重新框選或縮減成單一物件。 |
| 手機已有選取，點／拖框外物件或空白 | 不改選取、不偷偷取消、不啟動新框選；如需提示，簡短引導先取消。閱讀平移由既定閱讀／雙指手勢提供。 |
| 明確按「取消選取」 | 清空集合與框，再允許下一次點選／框選；不刪除物件或解除持久群組。 |
| 已選取框內縮放／旋轉控制點 | 控制點優先，調整既有集合，不被框內移動攔截。 |
| 單選文字、沒有持久群組限制時的再次短按 | 保留原位文字編輯入口，與超過移動門檻後拖移區分；長按成功不再觸發短按編輯。 |
| 電腦 | 保留點選、Shift 增減選及空白取消；拖曳可從整個框內起動，短按仍按明確的點選規則處理。 |

- 提供手機可發現的精簡「取消選取」按鈕或具名稱的圖示，建議放在選取情境工具／面板或緊鄰選取框，不能只藏在長按選單。本項是為本輪鎖定選取提供出口，不恢復舊版「完整包住／單頁／已選幾個」整排說明。
- 點關閉面板、縮放、頁面工具、開關選單、暫時失焦不視為「明確取消選取」。被遠端刪除或文件關閉等失效狀態另行安全處理，不能保留假的可編輯集合。
- 移動命中與可見外框使用同一座標系：單一旋轉物件按旋轉框內部測試，多選／持久群組按其顯示外框；PDF 原生旋轉、閱讀旋轉、縮放與捲動都要換算。
- 不新增會永久遮住內容的實心選取層；透明命中層不得蓋住縮放／旋轉把手、原位文字編輯器或面板。已選集合外框涵蓋其他未選物件時，**拖曳優先移動既有集合**，不誤拖下層物件。
- 復原／重做、建立／解除群組後維持合理選取，不能把「解除群組」當成「取消選取」。

## 7. 面板整體滑入滑出（第 8 點）

- 必須讓面板容器的背景、邊框、陰影、標題、控制項和內容一起移動；不能只讓文字淡入／平移，留下靜止空白底板。
- 釐清動畫節點與布局節點，可用整體面板外殼加內部捲動內容。外側按鈕跟隨面板邊緣，收合後停在可達位置；不得因獨立 CSS transition 不同步而先跳到另一處。
- 手機面板滑動全程不改閱讀區尺寸；桌面面板的預留空間需與整體動作協調，避免最後一幀大幅跳動。可使用獨立動畫層／一次布局結算等方法，但要量測閱讀錨點，不要求每幀重繪 PDF。
- 保留 v009 關閉立即 inert、完成後 hidden、草稿持續掛載、焦點回復、快速反向取消舊動畫及 `prefers-reduced-motion` 行為；新增整體容器動作不能退化這些保護。
- 建議沿用 180ms ease-out；減少動態效果時即刻切換。重新盤點屬性／圖片／頁面面板、搜尋、設定 Disclosure、浮動選單，依各自容器處理，不一律只動畫 children。
- 驗收必須查看動畫途中影格或錄影，確認背景與邊界位置真的連續變動。僅 timer／transform 字串／文字節點測試通過不算修復。

## 8. 可保存的物件群組（第 9 點）

### 操作與建議預設

- 建立群組保存成員關係；不是匯出圖片、合併筆跡或破壞性轉換。保留每個物件 ID、筆跡點、文字、圖片資產、角度與屬性，解除後可分別編輯。
- 建議第一版同頁至少兩個物件、每個物件只屬一個群組、不巢狀。選取已有群組加其他物件時，先展開完整成員聯集再建立新的平面群組，原關聯以可復原操作退役；只有一個既有群組時不重複建立空殼。
- 點任一成員或範圍碰到任一成員，選取擴充成完整群組；桌面 Shift 對整組增減選。整組可共同移動、縮放、旋轉、刪除及調圖層。
- 建立後保持新群組已選；解除後保持成員以暫時多選形式已選。手機必須明確取消後才重選，解除不暗中清空。
- 建立／解除瞬間的外觀、位置、尺寸、角度及圖層完全不變。不為了群組將原本交錯的圖層強制排成連續區塊；後續圖層命令針對完整成員集合，沿用 v009 明確的多選排序語意。
- 建議第一版整組選取時不直接啟動內部單一文字編輯；提供解除群組後編輯的清楚途徑。若另提供群組內編輯，必須明確進入／退出，不與手機保留選取及框內拖移衝突。

### 資料、同步與復原

- 可採因果版本化的 `groupId` 成員關聯，或獨立群組紀錄；先寫出模型與取捨。不要僅加 React state、localStorage，或把現有 `commitGroup` 重新命名就當成持久化群組。
- 若新增 `kind:'group'`，須完整更新目前把非 document value 視為 Annotation 的驗證、預覽、命中、匯出、衝突等流程；不能讓群組假物件被畫成未知註記。
- 建立、解除、移動、縮放、旋轉、刪除與相關圖層變更納入 expected heads、IndexedDB 交易和一次復原／重做。成員變動或其中一個已失效時整批拒絕，不能只改半個群組。
- **本機交易不代表跨裝置原子性。** 須設計完整會員一致性檢查與合併規則，涵蓋一個成員被兩端加入不同群組、解除對上移動、成員修改／刪除、重組及同時解衝突；全部版本保留，不用牆鐘或裝置優先覆蓋。
- 有會員／成員衝突時，相關群組不得排除衝突成員後繼續當正常群組修改；保留內容，顯示問題並能在衝突管理查看／選擇版本。解衝突後重新驗證群組一致性。
- 群組只剩一個有效成員時可作一般物件呈現，但不能在讀取時偷偷產生解除操作、清掉歷史或讓舊快照復活已解除關聯。完整原子操作的保存失敗也不得留下孤兒群組。
- `.pdfnote` 匯出／重新匯入、建立副本、合併及 Drive 快照須保留群組；舊檔無群組時照常讀取。群組 ID 必須在文件範圍解讀，建立副本後不得跨文件牽動原檔。
- 首次保存群組語意必須使用不支援群組的舊客戶端能明確拒絕的新文件 format（目前基線 5，通常接續 6；以實作當時版本為準）。不能只加 `groupId` 卻沿用 format 5，因為目前驗證容許未知欄位，舊版可能忽略關聯而直接改成員。只對未引入群組等新語意的舊文件保留舊格式；是否升資料庫版本依實際儲存需求與舊客戶端相容性決定，不清資料、不自動降版。新增群組 schema 的數量／引用／同頁／循環驗證保留原資安上限。

## 9. 右鍵與長按物件選單（第 10 點）

- 共用浮動選單，至少提供「建立群組」「解除群組」「刪除」；可整合四個圖層命令及手機「取消選取」。依選取內容顯示或停用不適用項目，不能顯示可按但沒有作用的指令。
- 桌面既有選取框內右鍵（包含空隙）操作整個集合；框外未選物件右鍵可選該物件／完整群組後顯示選單。無物件的空白處不冒出針對不存在物件的刪除命令。
- 手機已有選取時，框內長按操作既有集合，**框外長按不得靜默換選取或取消選取**。尚無選取時，長按物件可選取它／其完整群組並開選單。
- 建議長按約 500ms、抖動容許約 8 CSS px，依實測調整；超過移動門檻轉拖曳並取消選單計時，第二指／捲動／取消／失焦／切工具都停止計時。
- 建議物件長按啟用於選取／閱讀／頁面工具的閒置物件操作；筆刷正在書寫的長按拉直維持優先。正在文字輸入時保留原生複製貼上；縮放／旋轉控制點不兼作長按選單入口。若擴充到其他工具，須補足互斥規則。
- 長按成功後消耗該次 pointerup／click，不能立即誤觸文字編輯、重選、移動保存或選單項目。未按下命令只開選單不修改文件。
- 使用既有浮層避讓、單一選單、焦點及 keyboard 邏輯，另外支援指標位置／選取框錨定；不要用隱藏滿版按鈕代替。選單覆蓋、不擠版面，優先向上並按視窗邊界／軟鍵盤避讓。
- 支援外點／Escape 關閉，Shift+F10／選單鍵操作已選物件。關閉選單不取消手機選取；輸入框及非物件內容的原生右鍵功能保留，僅在處理 App 物件命令時阻止瀏覽器預設選單。
- 選單開啟後若選取 head 或會員關係被同步更新，關閉或停用失效命令；執行時再次驗證目標，不能將舊選單命令套到新集合。

## 10. 統一手勢優先順序與建議預設

先依作用區域與目前工具分流，再在該工具內判定優先順序：表單／對話框／選單 → 文件雙指縮放 → 該工具允許的控制點調整 → 框內拖移／有效的物件長按 → 該工具的單指操作。控制點與框內移動只在物件操作情境啟用；切畫筆、螢光筆、橡皮擦或文字工具時，保留的舊選取不能攔截書寫、擦除或輸入。閱讀／頁面工具的單指仍遵閱讀規則，開過右鍵／長按選單不代表改成拖移物件。雙指到來時只取消尚未保存的文件手勢，不強制完成未套用文字或表單。

以下是規劃建議，不冒稱使用者已逐項指定：同頁平面群組、至少兩個成員、單物件單群組、先解除再編輯成員、手機兩列常駐工具、約 96～112px 頂部目標、44px 操作目標、500ms／8px 長按、180ms 面板動畫。實作時可依證據調整並記入設計文件；十項已確認需求及第 6 點確認答案不得自行反轉。

## 13. 技術查核依據

- [MDN：Pointer Events 雙指縮放](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events/Pinch_zoom_gestures)：以 pointer 狀態及指距辨識捏合；實際文件錨點與同步渲染仍需本專案設計。
- [MDN：touch-action](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action)：手勢開始後再變更設定不影響當次手勢；規劃須在事件開始前配置處理範圍，避免全域禁止無障礙縮放。
- [MDN：VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport)：scale 可協助區分瀏覽器捏合與文件內部縮放；鍵盤也會影響可見視窗尺寸。
- [MDN：contextmenu](https://developer.mozilla.org/en-US/docs/Web/API/Element/contextmenu_event)：右鍵及選單鍵的事件入口；手機長按辨識及互斥由 App 另外處理。
