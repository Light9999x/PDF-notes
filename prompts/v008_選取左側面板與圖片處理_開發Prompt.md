# v008 — 選取、左側面板與圖片處理

日期：2026-09-19。基線：App 0.7.0、[v007](v007_單選文字編輯與可收合面板_開發Prompt.md)。狀態：規劃完成，尚未依本版實作或驗收。本次閱讀目前程式並查閱圖片處理 API 文件，未修改或啟動 App。

後續執行註記（2026-09-19）：依使用者要求完成 App 0.8.0 程式更動，包含手動去背；本機資料庫版本 6、圖片庫會員操作採文件 format 4。見 [實作與採用預設](../app/docs/V008-DESIGN.md)、[已測／待測紀錄](../app/docs/VALIDATION-V008.md)。未啟動 App 或服務，瀏覽器與真機仍未驗收；以下保留原規劃全文。

## 1. 已確認的七項更動

1. 選取工具下，點物件可單獨選取；Shift 點未選物件為增選，Shift 點已選物件為取消該物件。
2. 物件屬性可收合面板移到左側，開合按鈕移到面板外側。
3. 切換不同工具時工具列高度保持穩定，選取／文字與其他工具同高。
4. 插入圖片的預設顯示方向改為水平 0°，修正目前側轉 90° 的問題。
5. 旋轉控制點預設顯示在選取物件上方，不能出現在右側。
6. 使用者可以從圖片庫刪除圖片。
7. 評估新增圖片去背：選擇移除區域／顏色，或指定保留區域；遵守既有免費、本機、離線要求。

第 1 項取代 v006／v007「未選物件短按不選取」的規則，但不新增獨立 point 模式；方框／自由選取仍保留，預設方框。第 2 項取代右側定位，沿用 v007 預設展開及草稿保護。第 6 項取代「圖片庫不提供刪除」，但不因此授權連帶刪除頁面實例、原始檔或操作歷史。

## 3. 點選與 Shift 增減選

### 操作規則

| 手勢 | 選取結果 |
| --- | --- |
| 不按 Shift 點未選物件 | 只選該物件，清除其他選取。 |
| 不按 Shift 點多選集合中的一個物件，沒有拖曳 | 變成只選該物件。 |
| Shift 點未選物件 | 加入該物件，原集合保留。 |
| Shift 點已選物件 | 只移除該物件；移除最後一個後為空集合。 |
| 空白處拖曳 | 依方框／自由選取模式進行相交選取。 |
| 已選物件上拖曳超過門檻 | 沿用整組移動，不在 pointerdown 就把多選縮成單選。 |
| 縮放／旋轉控制點拖曳 | 控制點操作優先，不被 click 或 Shift 切換攔截。 |

- 使用 pointerdown 記住物件 ID、原集合及 Shift 狀態，pointerup 確認未形成拖曳才提交點選。pointercancel／失焦不可留下半套增減選或觸發文字編輯。
- 建議對未選物件起拖仍建立新圈選，與既有區域操作一致；Shift 拖曳框選是否增選不是本輪要求，先維持既有取代集合行為並記錄，不擅自加入另一套快捷鍵。
- 重疊物件以實際渲染順序最上層可編輯物件為命中目標；筆跡用線段與筆寬、文字／圖片用旋轉框，不用整個群組外接矩形的空隙攔截點擊。
- 保留單頁多選預設。跨頁 Shift 點選建議開始該頁的新集合，不隱性擴充跨頁群組操作；在設計紀錄說明，必要時一次簡短提示。
- 已刪除或未解決衝突物件不能自動選一個版本來編輯。Shift 只改選取集合，不產生文件操作、同步或 Undo 項目。

### 與文字及圖片情境協調

- 第一次點未選文字只選取；已單選文字再短按可依 v007 進入原位編輯，Enter／F2 入口保留。Shift 點文字一律只增減選，不開鍵盤／編輯框。
- 單選／多選改變時保留未套用屬性與文字草稿的既有保護，不能用新點選入口繞過預期版本檢查。
- 原位文字編輯內 Shift＋點擊及拖曳仍交給文字游標／選字，不觸發物件增減選；Delete 在輸入時只刪字。
- 圖片工具無待放置圖片時若沿用選取手勢，應共用相同判定，維持工具列／圖片面板情境一致。待放置圖片的落點操作優先，不意外選取底下物件。
- 手機可用點選、框選／套索；本輪不強制新增常駐多選開關。Shift 語意適用具鍵盤的桌面／裝置，不假設手機一定有實體鍵盤。

## 4. 左側面板與外側開合控制

- 將編輯器的可收合屬性面板移到左側，預設展開。建議圖片庫共用同一左側面板，維持單一情境區，不同時留下右側圖片欄；這是沿用共用面板架構的規劃解讀。
- 「按鈕外側」建議明確定義為面板外、朝閱讀區的右邊緣，獨立窄控制區；不是表單內容內的第一欄。收合後仍留在閱讀區左緣，可一次展開。
- 展開時由左至右為「面板內容 → 外側開合控制 → PDF 閱讀區」。按鈕的箭頭表示實際收合／展開方向，具名稱、焦點、aria-expanded 與內容關聯；桌面和手機均可達。
- 按鈕不隨長屬性內容一起捲走，不因面板 hidden／inert 被隱藏，也不以覆蓋 PDF 點擊區的透明大面積實作。保留足夠觸控範圍，避免與頁面控制點撞在一起。
- 收合釋出面板寬度；展開占位，窄版可採左側非模態覆蓋。適合寬度／整頁、作用頁置中、首尾留白、可見區計算必須納入左側遮擋的起始偏移，而非只扣寬度卻仍以原左緣置中。
- 檢查由 client 座標轉到頁面座標、圖片拖放落點、搜尋高光／捲入視野、旋轉把手可用空間及閱讀錨點，不能只對 CSS 做 right→left 文字替換。
- 同文件保留手動開合狀態，重新開文件預設展開；草稿、選取、正在組字內容及圖片待放置行為沿用 v007。面板換邊不是資料遷移，不改文件或同步紀錄。

## 5. 切工具時工具列等高

- 在相同 viewport、文字大小及搜尋／頁面設定展開狀態下，切畫筆、螢光筆、橡皮擦、選取、文字、圖片、閱讀時，頂部工具區高度保持一致，閱讀區不因工具設定列出現／消失而上下跳動。
- 建議共用一個有穩定高度的「目前工具設定」槽位。選取的方框／自由選取、文字顏色、筆刷顏色／尺寸及橡皮擦尺寸使用一致控件高度與垂直對齊；空工具仍保留槽位，不放假按鈕或長說明填空。
- 容器高度依斷點／內容可用空間配置，必要時採同一套可預測的兩列或局部水平捲動；不能只給 min-height，任由某工具換行變高，也不能以裁掉設定欄維持數字上的等高。
- 文字放大、手機橫向及軟鍵盤出現時重新適配整組高度，各工具仍使用相同布局預算。保留可讀字級及 44px 常用操作尺寸，不壓縮控件達成精簡。
- 使用者明確展開搜尋或頁面設定可以改變總高度；工具切換本身不應連帶開關這些區域。面板換頁或圖片載入不拉高頂部工具列。
- 驗收量測工具區與 PDF 閱讀容器頂緣的實際 bounding rect；字串長度、停用／選取狀態及載入中也納入，不只測 CSS class 或 style 值。

## 6. 圖片初始方向與旋轉控制點

### 圖片預設水平 0°

- 新增圖片在當前可見頁面中應正立、水平 0°，以不對稱測試圖（上箭頭、可讀字樣）確認；不得側躺 90°。圖片來源本身的攝影方向與使用者既有旋轉必須尊重。
- 拖放預覽、點選放置、保存後畫面、選取框／命中、重新開啟、衝突預覽與 PDF 匯出用同一方向定義。預覽正確而放開後翻轉亦屬未修好。
- 參照目前文字的可視角度計算，抽出適用一般矩形物件的放置函式，處理 PDF 原生 Rotate、App 頁面旋轉、CropBox、局部中心旋轉與落點錨定。圖片左上角／明確落點錨點不能在補償角度後跳到別處。
- UI 顯示角度與儲存的頁面本地角度可能不同，需經矩陣轉換；不要硬把所有資料 angle 改成 0，或無條件加減 90°。先確認頁面矩陣與 EXIF 解碼各自的方向作用，避免重複校正。
- 改的是新放置預設；既有圖片資料與使用者主動旋轉保持不變。去背衍生圖放入頁面亦遵守同一規則。

### 旋轉控制點預設在畫面上方

- 新選取物件或群組時，旋轉控制點顯示在畫面中選取範圍上緣中央外側，帶短連接線；不因頁面旋轉而跑到右邊。此「上方」以螢幕可見方向為準，不是物件本地 y<0。
- 建議將控制點定位於完整轉換後的畫面包圍範圍，再轉到對應渲染層；選取框本身仍對齊物件實際形狀，不把圖片扶正錯誤掩蓋成控制點改位。
- 保留自由角度旋轉與足夠命中區。按住控制點時固定旋轉中心及起始指標角度，以角度差更新，避免把移到上方的控制點當作物件原始角度而一按就跳轉。
- 建議非拖曳期間控制點保持在畫面上方；旋轉進行中可跟手勢自然移動，放開重新定位。這是交互預設，需記錄採用方式。靠頁面頂邊／選取極大物件時，優先保留控制留白或可見位置，不能被紙張裁切或左側按鈕擋住。
- 檢查單選／多選、物件 0／90／180／270／任意角度、頁面原生與 App 旋轉、zoom 及左右布局。縮放點、旋轉點與直接拖移優先序維持。

## 7. 從圖片庫刪除素材

### 使用者可見行為

- 每張縮圖提供可發現的「從圖片庫移除」操作，可透過更多選單或獨立按鈕；不能只靠滑鼠 hover，手機也可操作。點刪除不觸發縮圖拖放／放置。
- 建議以短提示說明「已放入頁面的圖片會保留」，完成後提供復原或明確重新匯入的途徑。這個操作不是刪除文件中的所有圖片實例，也不是保證立即釋放磁碟空間。
- 移除後庫內不再顯示縮圖，既有頁面實例、原始 bytes、編輯歷史、復原與匯出仍正常。歷史操作引用的資產不能被直接刪除，PDF 基底與原始檔更不能一起刪。
- 若該圖片正在待放置或拖曳中，移除時取消該暫存操作；已完成的頁面物件不受影響。正處理去背時需保護草稿，不在背景突然清掉來源。

### 同步與歷史：必要實作，不只隱藏縮圖

- 現有 `galleryHashes` 會從歷史物件補回圖片，merge 又是單純聯集；需新增可持久化、可同步的圖片庫會員新增／移除紀錄或等價墓碑，套用在歷史資產回推之後。不能只改 gallery 陣列或 React state。
- 建議同一 hash 的並行移除／保留採「移除優先於未觀察到移除的舊新增」，防止離線端或舊 `.pdfnote` 合併後復活；使用因果關係／操作 ID，不依裝置時間做最後寫入者勝出。這是會員規則建議，不取代既有註記物件衝突頁規則。
- 明確重新匯入相同 bytes、復原移除或選擇恢復，應產生觀察到現有移除的新恢復操作；不能讓永久 hash 黑名單阻止使用者日後重用。當同時另有未觀察到的移除時，依已記錄並行規則處理。
- 未使用素材也要保存會員移除狀態；原始 assets 可先保留，垃圾回收另行規劃。刪庫素材本身不產生頁面物件 tombstone。
- 更新 model 驗證、存取、複製文件、封裝／重新匯入、Drive 快照、合併及必要格式版本。舊格式缺少移除資訊時按原列表讀取；舊客戶端若會忽略新規則而使素材復活，須以格式／相容檢查拒絕不安全往返，不能宣稱沿用格式就自然相容。
- 需測合併冪等、交換順序、重複同步、離線移除、舊檔重匯入與明確恢復。App 重開仍不顯示已移除素材，頁面上的引用始終可讀。

## 8. 免費離線去背：可行性與首版範圍

### 技術評估結論

手動區域／顏色去背在現有網頁 App 技術架構上具可行基礎：Canvas 的 ImageData 可讀寫 RGBA 像素，因此可以將使用者選定區域的透明度設為 0；這是技術推論，尚未在本專案完成原型、效能或品質驗收。[MDN 像素處理](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Pixel_manipulation_with_canvas)

Canvas 合成操作亦提供遮罩合成方式；可使用像素 alpha 或遮罩實作，無需預設外部付費服務。[MDN globalCompositeOperation](https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/globalCompositeOperation)

大量處理可評估 Worker／OffscreenCanvas，並偵測支援及提供不阻塞操作的分批替代；API 能力不代表 Galaxy S24+ 大圖效能已通過。[MDN OffscreenCanvas](https://developer.mozilla.org/en-US/docs/Web/API/OffscreenCanvas)

以上資料查閱於 2026-09-19。首版規劃為使用者指示的去背，**不承諾 AI 自動辨識主體、毛髮級分割或任意背景一鍵完成**。不載入付費 API、不上傳圖片、不要求雲端處理；自動模型非本輪必要範圍。

### 建議最小可交付功能

- 入口位於圖片庫素材操作或單選圖片的屬性；開啟同一個精簡圖片處理工作區，顯示棋盤透明底及目前來源。這是圖片專用操作，不影響 PDF 文字／物件的圈選工具。
- 「移除區域」：方框／自由圈選區域轉透明。「保留區域」：保留圈內、圈外轉透明。也可用同一選取區配合保留／移除切換，不必建立大量新工具按鈕。
- 「按顏色移除」：點樣本色，調整容差，預設僅移除與點擊位置連通的近似色區域；「全部相近顏色」可作明確選項，避免同色主體也被無意移除。容差為色差門檻，不冒稱智慧分割。
- 提供預覽、復原／重做、重設、套用及取消。套用前只改草稿遮罩；區域操作和顏色操作共用一份遮罩，復原不重建或破壞原始檔。
- 先提供單一清楚的保留區域語意：確認圈選時建立「保留圈內」遮罩；若支援多區保留，應以明確增選模式聯集，不讓第二圈偷偷把第一圈主體清掉。刪除區域可逐次累加，預覽須完全反映結果。
- 選取路徑從顯示位置轉成原圖像素座標，圖片縮放、平移、頁面旋轉與 DPR 不得改變去背位置。工作區可用來源正立預覽，不把 PDF 的物件角度烘進原圖兩次。
- 建議維持原圖像素尺寸，以透明 PNG 產生新資產；不自動裁切邊界，避免既有物件尺寸與位置跳動。保留來源資產，對半透明邊緣保留原 alpha，不把原透明區填白。
- 圖片庫入口套用後新增去背副本；由頁面單一實例開啟時，可將該實例的 asset 改為新副本並保存歷史，其他共用來源的實例維持原樣。兩種入口的作用對象須在套用處清楚呈現，不默默批次換圖。
- 建議以新 hash 的 PNG 資產加既有 image 物件引用保存結果，原圖與歷史保留。首版可從原圖重做，但不承諾每個已套用遮罩步驟跨次開啟仍可編輯；若保存可重編遮罩，須另定版本與封裝相容，不能只存暫存 URL。
- 新副本進文件圖片庫、離線可用且可封裝／同步；透明度在編輯器、預覽、PDF 匯出一致，顯示棋盤不屬圖片內容。合併或儲存失敗不得留只有引用而沒有 bytes 的半成品。
- 大圖設像素／記憶體預算、可取消進度與過期工作隔離。允許較低解析度預覽，但輸出若需降採樣必須明示，不能偷偷降低原始素材。處理在本機完成，既有 JPEG／PNG 驗證與大小限制保留。

### 若遇實際不可行部分

先做最小離線原型驗證「區域遮罩、顏色連通選取、透明 PNG 及匯出」再整合；就已有能力交付可用範圍。若指定裝置效能或瀏覽器能力阻擋某方法，記錄可重現原因及替代方式，未支援按鈕不展示為可用。不以 AI 自動去背困難為由略過手動區域去背，也不只顯示介面但沒有結果。

## 9. 待驗收與實作順序

建議順序：先明確新選取／文字手勢，再處理左面板及等高工具列；共用圖片放置方向與控制點座標；定義圖片庫移除／恢復的同步資料語意；完成去背原型後整合。所有建議預設與實際採用方式分開記錄。

| 需求 | 驗收案例 |
| --- | --- |
| 1 | 點選單一、Shift 加／減、移除最後一個、重疊命中、點多選成單選、拖已選仍移整組、控制點優先、Shift 文字不編輯、原位文字 Shift 選字、取消手勢不殘留。 |
| 2 | 左側預設展開、按鈕在內容外；收合釋出空間，長內容不捲走控制。桌面／手機、fit-width／fit-page、手動縮放、搜尋定位與圖片落點正確，草稿和焦點不丟失。 |
| 3 | 同一 viewport 切所有工具，工具區高度及 PDF 起點不跳動；360／412px、桌面、短高度及文字放大下皆可操作，未裁掉工具。 |
| 4 | 非對稱測試圖在普通／旋轉 PDF、空白橫直頁、不同 App 旋轉下新放置皆正立；拖放預覽、落點、UI 0°、存檔、匯出一致，舊圖片角度保留。 |
| 5 | 單選／群組控制點在畫面上方，頁面及物件旋轉後不跑到右側；按下不跳角，任意旋轉、靠頁邊與小物件控制點仍可操作。 |
| 6 | 已使用／未使用素材移除、重開、雙端離線合併、舊檔重匯入、重複同步、恢復／同 hash 再匯入；庫內不意外復活，既有頁面、歷史及匯出無缺圖。 |
| 7 | 棋盤透明預覽、移除／保留圈選、連通色／全域色及容差、原 alpha、縮放後像素命中、復原／取消、原圖不改、單實例替換、PNG 往返／同步／PDF 透明度。大圖處理可取消、不阻塞必要 UI。 |

幾何、狀態、像素遮罩及合併可做不啟動服務的必要單元測試；瀏覽器工具列實際高度、字形／圖片方向、IME、手機記憶體及畫面仍需實測。依 [AGENTS.md](../AGENTS.md)，未經使用者明確要求，不啟動 App、服務、瀏覽器 App 畫面或會啟動服務的測試；未測項目列出，不反覆詢問，也不以舊版測試替代。
