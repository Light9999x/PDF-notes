## 1. 產品目標

製作可安裝於 Windows 電腦與 Android 手機的文件閱讀與筆記 App。以 PDF 作為統一閱讀及註記格式；若可將免費、本機可用的 PDF converter 整合至 App，則用來將 Word、圖片等非 PDF 檔案轉成 PDF 副本。若無法實作或整合，使用者已同意先略過轉換功能，不阻擋核心 App 交付。

已提供的本機功能全部可離線使用，包含閱讀、手寫、螢光筆、加入圖片、輸入文字、儲存及兩種格式的匯出；若有提供文件轉換，也必須能離線完成。跨裝置資料自動同步；不同裝置新增的筆跡、文字框與圖片等物件應全部保留，讓使用者之後自行整理。

**離線與同步的工程解讀：**沒有可用連線時，先完成本機保存並排入待同步佇列；與同步端或另一裝置恢復可用連線後再自動同步。完全沒有裝置間的連線時，無法即時交換資料。此規則不影響本機功能的離線使用。

核心流程：

**匯入支援的檔案並保留原始檔 → 需要且已有支援時本機轉成 PDF 副本 → 建立 App 工作文件並編輯獨立物件 → 儲存為 App 自訂格式 → 連線後透過 Google Drive 自動同步 → 至衝突管理頁查看各版本並擇一 → 匯出自訂存檔或合併 PDF**

## 4. 第一版範圍與實作建議

第 2 節的需求均納入目標範圍；以下導覽、管理與操作細節是實作建議。PDF converter 及依賴它的非 PDF 文件匯入可在無法實作時先延後；自動同步、獨立衝突管理頁、四類註記及可編輯存檔等核心功能仍須完成。

### 4.1 匯入與文件管理

- 匯入目標為 `.doc`、`.docx`、`.png`、`.jpg`、`.pdf`。PDF 與 App 自訂存檔須支援；其餘文件匯入按 converter 的實際支援情況提供，分別記錄平台、格式、已實作或延後狀態。
- PDF 直接作為閱讀基底；若有對應 converter，Word、PNG／JPG 可在本機轉為 PDF。多張圖片排序合併為建議操作細節。
- 匯入時保留原始檔內容，建立 App 管理的工作文件；使用筆記後以 App 自訂格式持續儲存，不回寫來源 Word、圖片或 PDF。
- 優先將免費 PDF converter 以程式碼或可合法整合的元件內建到 App；不預設使用者需要另裝轉檔工具。提供轉換的裝置須可斷網獨立完成，顯示進度與錯誤；無法實作的轉換可先略過，繼續交付核心功能。
- 未支援的文件格式應在匯入選單及錯誤訊息清楚標示，不把無法轉換的 Word 當成已可閱讀的文件。交付時列出實際格式支援表，不宣稱五種格式皆完成。
- converter 的延後不影響「將 PNG／JPG 插入現有 PDF 頁面作為可編輯圖片物件」，也不影響合併 PDF 匯出；這些仍是已確認的核心功能。
- 提供基本文件清單：文件名稱、最近開啟時間、重新命名與刪除。
- 轉換結果未成功保存前，不將匯入標示為完成。
- 不覆寫或刪除使用者原始檔；刪除應用程式內的文件時，說明會移除哪些副本與筆記。

### 4.2 PDF 閱讀

- 翻頁、捲動、縮放、跳至指定頁碼及記住閱讀位置。
- 有文字層的 PDF 可選取及搜尋文字。
- 圖片轉成的 PDF 可閱讀及註記；若未加入 OCR，不承諾可搜尋或選取圖片中的文字。
- 電腦適合鍵盤滑鼠操作，手機適合觸控，介面不只是等比例縮小。

### 4.3 筆記與註記

- 文字框：在頁面輸入文字，可編輯內容、移動、調整大小與樣式、刪除；便利貼可作為補充功能。
- 手繪筆跡：供滑鼠、手指或觸控筆使用，提供顏色、粗細與橡皮擦。
- 螢光筆：支援自由畫記及半透明色彩，不依賴 PDF 是否有文字層；選字標記可作為補充功能。
- 匯入圖片作為頁面上的獨立物件，支援移動、縮放與刪除，保留原圖片資產；這與「將圖片轉成 PDF 頁面」是不同功能。
- 每筆筆跡、螢光標記、文字框及插入圖片都保有獨立識別碼與編輯資料，不在儲存時合成單張不可編輯影像。
- 復原／重做，以及自動儲存與清楚的儲存狀態。
- 手機區分閱讀手勢與繪圖模式，避免捲動時留下意外筆跡。
- 觸控筆壓力感應與防誤觸需依裝置和實作驗證，不預先承諾所有裝置一致支援。
- 使用者目前沒有觸控筆。首版在 Galaxy S24+ 驗證手指畫筆、螢光筆、縮放、捲動、物件操作及文字輸入；在 i7-11800H 電腦驗證滑鼠繪圖與鍵盤編輯。保留觸控筆輸入設計，但不能將手指或模擬測試宣稱為觸控筆實機驗證，也不要求使用者購買設備。

### 4.4 保存與匯出

- App 的工作存檔正式採用 `.pdfnote` 副檔名，對使用者呈現為一個檔案。建議在檔案內分開封裝來源檔、閱讀用 PDF、可編輯筆記資料與圖片資產；內部容器及資料結構由開發決定。
- 單一檔案是可攜存檔的使用者介面要求，不要求每畫一筆就重新封裝整份檔案，也不要求雲端只能儲存一個整檔；工作儲存及物件同步可使用適合的內部結構。
- 筆記綁定固定的 PDF 副本；若重新轉換來源檔案，應建立新版本，避免舊筆記套到不同排版。
- 支援匯出合併 PDF，將頁面與目前有效的註記、文字及插入圖片合併為可分享內容，供其他閱讀器查看；以扁平化輸出作為實作方向，不承諾此 PDF 仍保有 App 的物件編輯能力。
- 必須支援匯出單一 `.pdfnote` 工作存檔，內含原始檔、閱讀用 PDF、全部註記物件、插入圖片資產及必要中繼資料。將存檔匯入 Windows 或 Android 後，所有物件仍可選取、修改及刪除。
- 工作存檔必須自足，不能只有原裝置的路徑或雲端下載連結；在另一裝置離線匯入後仍能完整開啟。
- 分享 PDF 與可編輯工作存檔是兩種用途不同的輸出；PDF 匯出方式不得破壞原工作存檔中的物件資料。
- 未處理的衝突版本與衝突標記必須隨自訂存檔保留。合併 PDF 只能輸出確定的有效版本；建議在匯出前要求處理輸出範圍內的衝突，避免默默替使用者選擇版本。
- 重新匯入 `.pdfnote` 時，以內部文件唯一 ID 辨識，不只看檔名；重新命名仍可辨識同文件，同名但不同 ID 的文件不可誤合併。
- 辨識到同一份文件時，提供「建立副本」與「合併」，不預設覆蓋；未選擇或取消時不修改現有文件。
- 「建立副本」產生新的文件 ID，作為獨立文件保存及同步，保留完整內容且不影響原文件。
- 「合併」沿用同一文件 ID 與物件合併規則：新增物件保留、重複物件不重建、並行版本標記衝突並送至衝突管理頁；保留必要刪除紀錄，避免舊存檔讓物件無故復活。
- 合併前檢查基底 PDF 版本及格式相容性；不相容時保留原資料並提示可建立副本，不將註記硬套到不同頁面排版。

### 4.5 自動同步與合併

**已確認行為：**兩台裝置編輯同一文件後，雙方新增的物件均保留，不以較晚儲存的整份檔案覆蓋另一份。

**同一物件的已確認衝突規則：**同時保留不同更動版本並標記衝突，使用者在使用時必須從版本中挑選其一。這與「不同 ID 的新增物件全部保留」不同；衝突版本屬於同一物件的候選狀態，不可自動當成幾個互不相關的新物件。

例如：Windows 新增兩筆手寫筆跡；Android 離線期間新增一個文字框及一張圖片。恢復連線並同步後，兩端都應看見這四個新增物件，而且每個物件都能繼續編輯或刪除。

實作建議：

- 以使用者自行連結的 Google Drive App 專用隱藏資料區（`appDataFolder`）交換資料，驗證對應授權與兩平台的存取及同步能力，不改用一般可見同步資料夾。
- 使用者要取得可攜存檔或分享文件時，透過 App 匯出 `.pdfnote` 或合併 PDF，再自行儲存或分享；隱藏的內部同步資料與可分享輸出分開處理。
- 物件合併由 App 負責，不能只把整份工作存檔放入雲端同步資料夾，就視為已實作雙方新增物件全保留。具體傳輸協定需避免兩端同時上傳時互相覆蓋。
- 不預設需要付費主機或付費中介服務。查核候選雲端方案的免費範圍及必要授權；空間或額度不足時提示同步暫停並保留本機變更，不自動升級或購買。
- 本機先儲存，再進行同步。同步不可阻塞編輯；狀態應區分「已存至本機」「待同步」「同步完成」與「同步失敗」。
- 依文件 ID、固定的 PDF 版本及物件 ID 合併；不同裝置新增物件使用全域唯一 ID。
- 每次變更使用唯一操作 ID，重試及重複接收不得產生重複物件；不要只靠裝置時間判定新舊。
- 同步內容包含基底 PDF、物件資料、圖片資產及必要的刪除紀錄。參照的資產未齊全前，不宣稱完整同步成功。
- 刪除以可同步的刪除標記記錄，避免舊裝置重連後讓物件意外復活；標記清理策略需考慮長期離線裝置。
- 同一物件並行修改時，保留全部候選版本及衝突標記，提供預覽／比較與擇一操作，不自動選擇最新版本。選定後更新有效版本並同步選擇結果。
- 修改與刪除衝突也套用擇一規則：將「已刪除」作為一個候選狀態，讓使用者選擇保留修改版或接受刪除；未選前不丟棄修改內容。
- 使用者尚未處理衝突時，可持續本機保存並同步完整衝突資料，不以解決衝突為同步的前提。建議允許閱讀及編輯其他物件，操作衝突物件時提示先擇一，避免整份文件無法使用。
- 衝突解決操作需記錄它處理的版本集合；若兩台裝置又做出不同選擇，或新收到未涵蓋的版本，再標記衝突，不依照裝置時間默默覆蓋。
- 兩台裝置對同一 Word 各自轉出的 PDF 不保證版面一致；同步時使用同一基底 PDF 版本，不直接把註記套到另一份重新轉出的 PDF。
- Android 背景同步的時機需實測；規劃啟動 App、回到前景及可用連線恢復時補同步，不承諾系統限制下仍能持續即時背景同步。

### 4.6 獨立衝突管理頁
