## 3. 功能一：資料夾管理

### 3.1 使用流程

1. 在「我的文件」提供「新增資料夾」入口。
2. 輸入名稱並建立；完成後可進入該資料夾。
3. 在文件選單提供「移動到資料夾」，選擇目的地或移出到「未分類」。
4. 進入資料夾後只顯示其中的未刪除文件；可返回全部文件或未分類。
5. 在資料夾內匯入文件或新建空白文件時，建議自動歸入目前資料夾。

### 3.2 建議行為與邊界

- 資料夾是 App 內的分類，不是操作使用者磁碟上的真實資料夾，也不是在 Google Drive 建立一般可見資料夾。
- 每個資料夾使用獨立 ID，名稱可修改；文件透過 ID 指向資料夾，不因資料夾改名失去歸屬。
- 移動文件只更新分類資料，不更換文件 ID、不複製 PDF，也不影響既有筆跡及版本歷史。
- 名稱去除頭尾空白，拒絕空名稱；同層重名以提示並請使用者修改作為建議預設。
- 本輪先以單層資料夾為建議範圍；巢狀資料夾、拖曳排序及批次搬移另列後續，避免把未指定功能默認納入。
- 建議首輪只允許刪除空資料夾；非空時提示先移出文件，不連帶刪除筆記。
- 「全部文件」是檢視方式，不是另一份資料副本；「未分類」顯示沒有有效資料夾歸屬的文件。
- 文件改名、刪除／還原、搜尋與衝突標記應與分類一致；建議搜尋範圍遵循目前檢視並標示清楚。
- 舊版文件沒有資料夾資訊時，應出現在未分類及全部文件，不要求重新匯入。

### 3.3 同步、存檔與競爭情況

以下是配合既有同步需求的實作建議：

- 資料夾新增、改名、刪除及文件移動，採可合併、可重試的變更紀錄；不可用一台裝置的完整清單覆蓋另一台。
- 資料夾是文件庫層級資料；目前文件版本圖以單份文件為中心，不應塞入虛假的 PDF 文件來承載分類。
- 兩端同時新增不同資料夾都保留。若同步後出現同名不同 ID 的資料夾，不自動合併或刪除，可提示改名。
- 兩端把同一文件移到不同資料夾，或同時修改同一資料夾名稱時，保留候選狀態並標記為管理資料衝突。可擴充既有衝突管理頁呈現分類衝突，不假裝它是頁面筆跡。
- 文件移動不應與改名互相覆蓋；應分開追蹤獨立屬性，或使用能保留雙方更動的資料結構。
- 某端刪除空資料夾時，另一端可能離線移入文件。合併後不可因此刪除或隱藏文件：保留內容，暫顯示於未分類或待處理分類，並提示處理。
- 分類有衝突或資料夾尚未下載時，文件仍可從全部文件開啟，不讓分類問題阻塞閱讀與註記。
- 單一 `.pdfnote` 仍是單份文件的可攜存檔，不自動夾帶整個文件庫的其他文件或資料夾樹。
- 建議匯入為新文件／副本時放入目前資料夾，若未指定則未分類；合併至既有文件時保留其當前分類，不讓舊存檔覆蓋新的整理結果。內部 ID、歸屬資訊及歷史如何分層需在實作時明確設計。

## 4. 功能二：新建空白文件

### 4.1 使用流程

1. 在「我的文件」及資料夾檢視中提供「新建空白文件」，與「匯入文件」並列。
2. 開啟建立視窗，輸入名稱並選擇「直式」或「橫式」。
3. 建議先提供固定 A4 白底一頁，直式為預設；選擇方向時顯示版面示意。
4. 按下建立，在本機產生空白 PDF 頁面、建立文件 ID 與初始中繼資料，保存成功後開啟編輯器。
5. 直接使用畫筆、螢光筆、文字與圖片工具，沿用自動儲存、復原／重做、同步、衝突管理及兩種匯出。

### 4.2 建立與保存規則

- 空白文件不需要使用者提供來源檔案，不需要 Google 登入或網路。
- 空白 PDF 的產生可優先沿用專案既有 `pdf-lib`，不需要為這個功能完成 Word converter。
- 方向決定 PDF 頁面的真實寬高，不能只旋轉或拉伸畫面；橫式與直式在閱讀、縮放、座標及匯出時都必須一致。
- 建立時一次產生固定的基底 PDF，之後同步及匯入沿用同一份資料與雜湊，不讓各裝置重新生成不同基底。
- 目前資料模型要求原始資產與 PDF 資產。新建文件沒有外部來源，建議把最初生成的空白 PDF 作為不可變初始基底，必要時同時對應這兩個欄位；不能捏造使用者曾匯入 Word 或 PDF。
- 建議在介面或文件資訊中區分「匯入文件」與「新建文件」；新建文件的「匯出原始檔」若保留，應清楚表示輸出的是初始空白 PDF。
- 文件必須有獨立 ID，即使兩份空白 PDF 內容相同，也應能各自編輯，不可因資產雜湊相同而合成同一份文件。
- 在資料夾內建立時沿用該資料夾歸屬。取消不建立文件，失敗不留下半完成文件，不將重複按鈕操作變成意外重複文件。
- 可在沒有任何註記時保存、重新開啟及匯出 `.pdfnote` 或 PDF；空白內容不是損毀文件。
- 建立後改方向、插入／刪除頁面、不同尺寸混合頁、無限畫布、格線及橫線紙，均未被本輪明確要求，先列後續選項。不要直接改寫已有人手寫筆跡的固定 PDF 基底。

## 6. 建議驗收情境

- 建立資料夾、改名、進出分類及重開 App，內容及歸屬正確保存。
- 舊資料升級後文件不遺失，沒有分類的文件可從未分類及全部文件找到。
- 文件移入／移出資料夾後，文件 ID、筆跡與來源內容不變；非空資料夾不被連帶刪除。
- 若採本文件建議的分類同步範圍：離線新增不同資料夾、雙端移動同文件、改名／移動並行、刪資料夾／移入文件競爭，均不丟資料，重試不重複建立。
- 匯入新存檔、副本與合併時，資料夾歸屬符合規則，舊存檔不覆蓋既有分類。
- 離線分別建立直式及橫式空白文件，頁面真實寬高正確；取消不建檔，保存失敗有提示。
- 兩份相同尺寸的空白文件有不同 ID，可獨立編輯及同步。
- 新建文件加入四類註記後，保存、重開、匯出 `.pdfnote`、另一端匯入後仍可編輯；合併 PDF 的方向、內容與位置正確。
- 沒有註記的空白文件也可正常保存及匯出；初始 PDF 基底保持不變。
- 已有匯入文件、衝突解決、重複匯入副本／合併流程沒有被新功能破壞。
- Windows 11 25H2 的滑鼠鍵盤及 Galaxy S24+／Android 16 的觸控版面需驗證；沒有實機時明列未驗證，不將窄螢幕模擬或自動化測試稱為實機驗收。
- 真實 Google Drive 仍需實際授權及雙端驗收；模擬傳輸測試只證明所測協定情境，不宣稱真實同步已通過。
