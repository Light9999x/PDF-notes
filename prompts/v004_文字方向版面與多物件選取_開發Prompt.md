# v004 — 文字方向、桌面版面與多物件選取

整理日期：2026-09-18。狀態：規劃完成，尚未依本版實作或驗收。

延續 [v003](v003_編輯閱讀拖放與專案結構_開發Prompt.md)，保留 [v001 核心基線](v001_核心功能規劃與開發Prompt.md) 與 [v002](v002_資料夾與空白文件_開發Prompt.md) 未被新需求取代的規則。整理時根 README 顯示 App 0.3.1；prompt 版本與 App 發布版本分開計算。本次僅更新規劃文件，未啟動 App，未判定畫面問題的確切根因。

## 1. 使用者確認的新增更動

1. 文字框方向仍有問題：0° 應呈現水平橫向，文字方向正確。
2. 電腦版應預留物件屬性面板的空間。
3. 選取除點選外，增加「方框」與「自由選取（自己圈）」；可一次選取範圍內的所有物件。
4. 螢光筆準心與筆刷相同，使用十字準心。

第 4 項取代 v003「只有筆刷使用十字」的規則。橡皮擦仍為可調大小的圓圈，大小須與實際作用範圍一致。

## 2. 規劃解讀與建議預設

以下是讓後續開發可直接執行的建議，並非使用者逐項確認的偏好；如實作有更合適的選擇，應在設計紀錄說明。

| 項目 | 建議預設與界線 |
| --- | --- |
| 文字方向與角度 | 保留 v003 的水平／垂直排字選項。預設為水平排字、0°；切換垂直排字是獨立操作，不以旋轉 90° 假裝直排。 |
| 0° 基準 | 使用頁面本地座標；未額外旋轉的頁面中，水平排字在 0° 必須由左至右、字形正立。頁面整體旋轉與文字自身角度分開處理。 |
| 區域選取判定 | 預設選取完整落在範圍內的物件，包含邊界；僅擦到邊緣或只有中心點進入範圍不算。工具提示應說明「完整包住物件」。 |
| 選取頁面範圍 | 第一輪以單頁內多選為範圍；跨出起始頁面時裁切選取區域，不悄悄選到其他頁。跨頁多選另行規劃。 |
| 多選後操作 | 建議支援整組移動、刪除與復原／重做；共同屬性可批次修改。整組旋轉、縮放及永久群組不列入本次必要範圍。 |
| 桌面屬性欄 | 保留固定側欄位置，無選取時顯示提示；寬度沿用合理現值，再依內容調整，不要求新增拖拉調寬功能。 |

文字角度歸零不應偷偷把使用者明確選擇的垂直排字改成水平；新文字與水平排字模式則必須符合「0° 水平向右」。這是延續既有兩種獨立控制的規劃解讀。

## 3. 文字方向修正

- 以實際顯示為準，不能只因資料中的 `angle` 等於 0 就判定修正完成。以「中文 ABC 123，測試」檢查左右順序、字形方向與標點，避免倒立、鏡像或整段轉成直向。
- 追查 PDF 頁面轉換、CropBox／原點、Y 軸方向、註記座標、文字局部旋轉中心與渲染流程。不要在未釐清原因時統一加減 90°，也不要同時在父層與文字層重複旋轉。
- 水平與垂直排字分開保存，角度只表示文字框自身旋轉。角度正負方向與 UI 顯示一致，90°、180°、270° 及任意角度都要有一致結果。
- 編輯器、衝突版本預覽、重新開啟、`.pdfnote` 匯出／重新匯入與合併 PDF 匯出，使用同一套方向定義。SVG 與 Canvas 不得各自套用相反基準。
- 選取框、拖曳與命中判定須跟隨文字的實際旋轉位置，不可只修顯示而留下錯位的互動範圍。
- 舊文件缺少方向或角度時，以讀取預設水平／0° 處理。不可為補預設值而改寫既有不可變操作內容，避免相同操作 ID 在同步時變成不同內容。
- 不全面重設既有文字的角度；若確有某一舊版資料需遷移，先確認可辨識條件、備份與往返相容策略。
- 驗收包含原生頁面旋轉 0／90／180／270°、非零 CropBox、橫直式紙張及 App 的頁面旋轉。文字應跟隨頁面本地座標變換；不得把頁面旋轉額外寫入文字角度。

## 4. 電腦版預留屬性面板空間

- 桌面編輯區明確分為閱讀區與右側屬性欄；無選取、單選、多選切換時都保留側欄占位。
- PDF 可視寬度、置中與「符合寬度」縮放須扣除側欄及間距。側欄不得蓋住頁面、物件、捲軸或必要工具。
- 選取物件不應讓整份 PDF 突然左右跳動或重設閱讀位置。視窗尺寸或可用空間改變時，以容器尺寸重新計算，保留合理的閱讀錨點。
- 屬性欄內容可獨立捲動；長文字、多選提示及工具列不能撐大版面，造成頁面被擠出可視區。
- 無選取時顯示操作提示；單選顯示該物件屬性；多選顯示選取數量與可共同編輯的屬性。不同值顯示「多個值」，不得自動套用第一個物件的值。
- 此要求針對電腦版。窄視窗與 Android 可採可收合面板；保持足夠操作空間，不強制手機永久保留桌面側欄。

## 5. 方框與自由選取

### 操作方式

- 保留點選單一物件，新增清楚可見的「方框」與「自由選取」模式。切換模式不能新增筆跡或觸發橡皮擦。
- 建議以短按／點擊選單一物件；在區域選取模式下，拖曳超過門檻後開始畫選取範圍，即使起點位於物件上也如此。
- 方框模式按住拖出矩形；自由選取模式沿指標軌跡畫出範圍，放開時連回起點。過短或退化的軌跡視為點選，不產生意外大範圍選取。
- 操作中顯示邊界及半透明區域；放開後顯示命中的所有物件與選取數量，不只選最上層物件。
- 每次完成範圍選取預設取代目前選取集合。增選／減選快捷鍵屬可選延伸，不應成為手機使用多選的必要條件。
- 若支援整組移動，提供明確的移動把手或模式，避免拖曳既有選取內容時，無法判斷是移動還是開始另一個圈選。
- Esc、指標取消或切換工具時取消尚未完成的手勢，保留取消前選取，不寫入文件。已完成選取可用「取消選取」清除。
- 觸控需區分選取與頁面捲動；提供清楚的工具模式，保留可用的閱讀捲動方式，不讓 Android 全頁拖曳永遠被圈選攔截。

### 選取幾何與物件範圍

- 支援手寫筆跡、螢光筆、文字框及匯入圖片。PDF 本身的文字與圖像是基底內容，不算可編輯註記物件。
- 所有指標座標先轉為起始頁面的本地座標；縮放、捲動、水平／垂直閱讀及頁面旋轉不得改變同一範圍的命中結果。
- 筆跡考慮整條折線及筆寬；文字與圖片考慮旋轉後的物件框。可先用包圍盒篩選，再做實際完整包含判定，不能只檢查中心點或包圍盒是否相交。
- 自由選取允許凹多邊形；建議自交路徑採奇偶填充規則，畫面填色與幾何判定一致。僅檢查所有頂點仍可能讓物件邊穿出凹陷，需正確處理邊段。
- 被其他註記遮住但完整在範圍內的物件也須選入。已刪除物件排除；未解決衝突依現行保護規則處理，不能默默挑一個版本操作，略過時要提示。
- 選取框、控制把手和圈選軌跡只屬於編輯介面，不儲存為註記，不同步，不出現在匯出 PDF。

### 多選狀態與資料保護

- 使用物件 ID 集合維護選取。切換文件時清除；物件刪除、同步更新及虛擬化卸載後，清理或更新選取狀態，不留下失效屬性面板。
- 建議批次移動時保留各物件相對位置，批次刪除仍建立各物件的刪除操作。一次手勢／批次操作對應一次復原與重做。
- 批次修改沿用既有操作紀錄、預期版本檢查與衝突保護；途中版本改變時不得只寫入部分物件，或覆寫另一裝置的修改。
- 不同類型的多選只提供適用於整個集合的共同屬性；文字方向、字體等可限制於全為文字框時使用。混合值必須在使用者明確修改後才更新。

## 6. 準心規則

| 工具 | 準心 |
| --- | --- |
| 筆刷 | 十字 |
| 螢光筆 | 與筆刷相同的十字 |
| 橡皮擦 | 圓圈，跟隨大小設定、縮放與實際擦除範圍 |
| 文字／選取等其他工具 | 保留適合該操作的準心，不因本版變更全部改成十字 |

切換工具、開始與結束手勢、跨頁及離開畫布時不得殘留前一工具的準心；觸控沒有懸浮指標時不強制常駐滑鼠準心。

## 7. 開發切入點與驗收

整理時靜態閱讀的切入點如下；後續實作前應重新確認當下版本，不以此表當成根因結論。

| 位置（相對於 app/） | 目前觀察與後續方向 |
| --- | --- |
| `src/components/Editor.tsx` | 現有單一 selected ID、文字屬性與工具準心判斷；規劃改為多選集合、手勢區分及批次操作。已有批次提交機制可評估沿用。 |
| `src/components/AnnotationShape.tsx`、`src/core/render.ts` | SVG 與 Canvas 的文字排字及旋轉；需核對兩者與實際頁面座標。 |
| `src/core/geometry.ts` | 頁面矩陣、旋轉與命中判定；補入方框／套索完整包含幾何。 |
| `src/style.css` | 已有屬性欄樣式，仍需確認條件渲染與容器可用寬度，實現穩定占位。 |
| `src/components/ReaderPage.tsx` | 頁面按需渲染，需保護進行中的選取手勢及必要狀態。 |

建議驗收清單（以下均尚未因本次規劃而執行）：

1. 新文字預設水平／0°，中英數正立且順序正確；任意角度、直排及旋轉頁面符合定義。
2. 編輯、衝突預覽、關閉重開、`.pdfnote` 往返及匯出 PDF 的文字方向一致，舊檔不被批次改角度。
3. 桌面無選取／單選／多選保留屬性欄，頁面不被遮擋或突然跳位；測試不同視窗寬度、系統縮放與面板長內容。
4. 方框與凹形自由圈選可同時選到四類物件，處理完整包含、擦邊、重疊、旋轉、粗筆跡及空集合。
5. 相同頁面區域在不同縮放、捲動與展示方向下，選取集合一致；取消手勢不改資料，切文件不殘留選取。
6. 若實作批次移動／刪除／屬性修改，檢查一次復原／重做、版本競爭與原子性，不遺失其他裝置修改。
7. 筆刷／螢光筆準心一致；橡皮擦圓圈與大小調整功能不退化。
8. Windows 滑鼠鍵盤及 Galaxy S24+ 觸控分別記錄實測結果；未取得真機或未獲啟動指示的情境標為未測，不冒稱通過。

遵守根目錄 [AGENTS.md](../AGENTS.md)：除非使用者明確要求啟動，不自動執行 App、伺服器或開啟 App 畫面，也不執行會啟動服務的整合測試。可執行不啟動服務的靜態檢查、單元測試及建置；視覺與實機驗收保留清單及未測狀態。
